# Примеры: приём апдейтов и отправка с ограничителем

Компилируемый учебный код к статьям раздела. Разобраны только те поля Bot API, которые нужны для механики приёма и отправки: реальный бот описывает типы полнее и обычно берёт их из библиотеки-обёртки.

## Файлы

- [updates.go](./updates.go) — `Poller`: длинный опрос с корректным сдвигом смещения. Разбор в [01-receiving-updates.md](../01-receiving-updates.md).
- [sender.go](./sender.go) — `Sender`, `Classify`, `Queue`: два ограничителя частоты, классификация отказов и очередь с приоритетом. Разбор в [03-rate-limits-and-queue.md](../03-rate-limits-and-queue.md) и [07-errors-and-degradation.md](../07-errors-and-degradation.md).
- [tgbot_test.go](./tgbot_test.go) — тесты на классификацию ошибок, приоритет очереди и арифметику смещения.

Запуск:

```bash
go test -race ./docs/senior-golang-study/08-networking-and-api/protocols/05-integration-patterns/telegram-bot-api/examples/
```

## На что смотреть в коде

- `Poller.Run` сдвигает смещение только после того, как обработчик вернул `nil`: до этого момента апдейты ещё можно получить заново, после — уже нет.
- `maxUpdateID` берёт максимум по пачке, а не последний элемент: при webhook апдейты приходят вперемешку, и привычка считать по максимуму дешевле.
- `NewPoller` задаёт таймаут клиента больше таймаута опроса — иначе клиент рвёт соединение раньше ответа сервера.
- `redactToken` вырезает токен из текста ошибок: он входит в каждый адрес Bot API и в ссылку на скачивание файла.
- `Sender.Send` ждёт на обоих ограничителях до вызова: превышение предела обходится дороже, чем ожидание очереди.
- `chatLimiter` создаётся с `burst = 1`, поэтому пауза в чате не накапливает право на пачку сообщений подряд.
- `Classify` относит незнакомый код ошибки к временным отказам: содержимое `error_code` в документации помечено как способное измениться.
- `Deliver` не расходует лимит попыток на ответ `429` — задержку там называет сервер, а от бесконечного цикла защищает `ValidUntil`.
- `Queue.Next` использует два `select`: первый с `default` даёт интерактивной очереди право первого выбора, второй блокируется на обеих сразу.

## Чего в примерах нет

- Дедупликации по `update_id` — она разобрана в [02-update-idempotency.md](../02-update-idempotency.md) и требует внешнего хранилища.
- Хранения прогресса рассылки: очередь здесь в памяти и не переживает перезапуск.
- Общего ограничителя для нескольких экземпляров: `rate.Limiter` считает частоту только своего процесса.
- Разбора конкретных типов апдейтов, клавиатур, файлов и состояния диалога.
