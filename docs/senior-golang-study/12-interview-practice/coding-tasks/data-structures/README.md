# Задачи на структуры данных

В этом разделе собраны не только алгоритмические упражнения, но и небольшие
инженерные реализации. В них важно определить контракт, выбрать структуры
данных, обосновать сложность операций и обсудить конкурентный доступ,
ограничение памяти и поведение на граничных случаях.

## Материалы

1. [LRU Cache](./01-lru-cache.md) — вытеснение давно не использованных записей
   через хеш-таблицу и двусвязный список.
2. [Top-K Elements](./02-top-k.md) — поиск наибольших или наиболее частых
   элементов с ограниченной памятью.
3. [Bloom Filter](./03-bloom-filter.md) — вероятностная проверка принадлежности
   с контролируемыми ложноположительными ответами.
4. [Trie](./04-trie.md) — префиксное дерево для поиска и автодополнения.
5. [Sliding Window Counter](./05-sliding-window-counter.md) — подсчёт событий
   за скользящее окно времени.
6. [External Merge Sort](./06-external-merge-sort.md) — сортировка данных,
   которые не помещаются в оперативную память.
7. [LFU Cache](./07-lfu-cache.md) — вытеснение наименее часто используемых
   записей за ожидаемое `O(1)`.

## Что проверяют задачи

| Задача | Основная идея | Инженерный контекст |
| --- | --- | --- |
| LRU Cache | `map` + двусвязный список | bounded cache, cache pollution от сканирования |
| LFU Cache | `map` + списки частот | удержание действительно горячих ключей |
| Top-K | min-heap размера `K` | потоковая аналитика, heavy hitters |
| Bloom Filter | битовый массив + несколько хешей | предварительная фильтрация дорогих lookup |
| Trie | дерево по символам или сегментам | autocomplete, маршрутизация, prefix search |
| Sliding Window | журнал событий или временные бакеты | rate limiting, метрики, обнаружение аномалий |
| External Merge Sort | отсортированные раны + k-way merge | объём данных значительно больше RAM |

Задача считается решённой не после написания основного метода, а после ответа
на вопросы о семантике обновления, пустой ёмкости, дубликатах, порядке при
равенстве, росте памяти и конкурентном доступе.

---

## Оценка сложности

| Структура | Основные операции | Дополнительная память |
| --- | --- | --- |
| LRU Cache | ожидаемое `O(1)` для `Get` и `Put` | `O(C)` |
| LFU Cache | ожидаемое `O(1)` для `Get` и `Put` | `O(C)` |
| Top-K через heap | `O(log K)` на обновление | `O(K)` без полного подсчёта частот |
| Bloom Filter | `O(H)` на `Add` и `Contains`, где `H` — число хешей | `O(M)` бит |
| Trie | `O(L)`, где `L` — длина ключа | зависит от общих префиксов |
| Sliding Window | зависит от точности: от `O(1)` до числа событий в окне | зависит от модели окна |
| External Merge Sort | `O(N log N)` сравнений и несколько полных I/O-проходов | ограниченная RAM + временные файлы |

Для операций на основе Go `map` под `O(1)` понимается ожидаемая, а не строгая
худшая сложность. Для cache `C` означает ёмкость, а не число когда-либо
увиденных ключей.

## Общие инженерные вопросы

- **Контракт —** какие операции меняют внутренний порядок или статистику и что
  происходит при некорректной конфигурации.
- **Ограничение памяти —** какие объекты удерживаются структурой и действительно
  ли размер ограничен заявленной ёмкостью.
- **Конкурентный доступ —** `Get` у LRU и LFU изменяет метаданные, поэтому обычно
  требует эксклюзивной синхронизации, а не только `RLock`.
- **Наблюдаемость —** полезно различать hit, miss, eviction, expiration и отказ
  принять запись.
- **Эксплуатация —** TTL, фоновые goroutine, callbacks и persistence меняют
  lifecycle даже небольшой структуры данных.

## Политики вытеснения cache

| Политика | Что вытесняется | Когда полезна | Основной риск |
| --- | --- | --- | --- |
| LRU | запись без недавних обращений | временная локальность | последовательный scan вытесняет горячие ключи |
| LFU | запись с минимальной частотой | стабильное распределение популярности | когда-то горячий ключ может удерживаться слишком долго |
| FIFO | самая старая вставка | нужен дешёвый и предсказуемый порядок | обращения не влияют на решение |
| TTL | запись с истёкшим сроком | данные теряют актуальность по времени | без cleanup истёкшие записи продолжают занимать память |
| Random | случайная запись | цена точного порядка выше его пользы | качество вытеснения менее предсказуемо |

На практике политика вытеснения не заменяет политику допуска: система может
сначала решить, заслуживает ли новый ключ попадания в cache, а уже затем выбрать
жертву. Поэтому промышленные алгоритмы вроде TinyLFU сложнее чистого LFU.
