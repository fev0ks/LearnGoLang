# `sync.Map`: выбор структуры, контракт и внутреннее устройство

`sync.Map` — специализированная конкурентная map из стандартной библиотеки Go. Она даёт безопасный доступ из нескольких goroutines и атомарные операции над одним ключом, но не заменяет обычную типизированную `map` под блокировкой во всех сценариях.

В Go 1.24 `sync.Map` перешла на concurrent hash-trie; это устройство сохраняется в проверенной для статьи реализации Go 1.26. Поэтому материал разделён на публичный контракт, актуальную и историческую реализации, а затем практические приёмы: читателю не нужно одновременно держать в голове API, memory model, устройство дерева и benchmark.

## Минимальная ментальная модель

Публичная `sync.Map` — тонкая оболочка:

```text
sync.Map
└── внутренняя HashTrieMap[any, any]
    └── root
        └── дерево по частям hash
```

- `Load` проходит дерево по атомарно прочитанным указателям и не берёт mutex узлов.
- Изменение блокирует только тот внутренний узел, чей дочерний указатель нужно заменить.
- Один вызов `LoadOrStore`, `Swap` или CAS атомарен для одного ключа.
- Несколько вызовов и несколько ключей не образуют транзакцию.
- `Range` не создаёт согласованный snapshot.

Этого достаточно для выбора структуры. Поля узлов, теги `entry`/`indirect`, расширение ветви и очистка дерева разобраны отдельно и на одном сквозном примере.

## Быстрый выбор

| Требование или нагрузка | Обычно выбрать |
| --- | --- |
| Нужны типы, `Len`, snapshot или invariant нескольких ключей | `map[K]V + Mutex` |
| Ключ записывается один раз и часто читается | Измерить `sync.Map` |
| Goroutines меняют в основном непересекающиеся ключи | Измерить `sync.Map` или sharded map |
| Нужна атомарная операция над одним ключом | Рассмотреть `sync.Map` |
| Один горячий ключ постоянно меняется | Отдельный `atomic` или lock |
| Contention ещё не измерен | Начать с `map + Mutex` |

`sync.Map` оптимизирована под конкретные профили доступа (`access patterns`). Выбор подтверждается benchmark с реальным соотношением чтений, записей и удалений, распределением ключей и числом goroutines.

## Версии

| Версия Go | Реализация `sync.Map` |
| --- | --- |
| Go 1.24–1.26 | concurrent 16-way hash-trie |
| Go 1.23 и старше | два индекса `read`/`dirty` и promotion по `misses` |

Это детали реализации (`implementation details`), а не часть публичного API. Контракт методов и гарантии memory model нужно отличать от конкретного устройства текущего исходника.
