## С чего начать

Если непонятно, «как это вообще работает в дереве», порядок такой:

1. Запустить [crud](./crud/) и посмотреть на вывод — сначала просто как на API.
2. Прочитать в его README разбор `Store` → `Load` → `Swap` → `Delete` на трёх ключах: там видно, в какой момент появляется новый уровень и почему читателю не нужна блокировка.
3. Запустить [tree-shape](./tree-shape/) с `-n=10` и сверить руками нибблы hash с номерами ветвей в напечатанном дереве.
4. Увеличить `-n` до миллиона и посмотреть, что глубина остаётся меньше шести уровней, а накладные расходы на узлы — нет.

## Оговорка про воспроизводимость

`crud` работает с настоящей `sync.Map`, и его вывод достоверен — кроме порядка обхода в `Range`, который не определён и меняется между запусками.

`tree-shape` — **модель**, а не внутренности реальной map. Настоящее дерево недоступно извне, а runtime хэширует ключи своей функцией со случайным seed на каждую map. Совпадают правило раскладки по четыре бита на уровень и статистика формы; конкретные номера ветвей — нет. Подробнее — в [README примера](./tree-shape/README.md).
