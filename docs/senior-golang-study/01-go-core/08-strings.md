# Strings: внутреннее устройство и ловушки

Строка в Go — частая тема на интервью, потому что за простым `string` прячется несколько неочевидных вещей: это **immutable заголовок над байтами в UTF-8**, а не массив символов. Из этого вытекают все «странные» поведения: `len` считает байты, `s[i]` отдаёт байт, `range` отдаёт руны, а конверсии стоят аллокаций.

## String header: указатель + длина

Переменная типа `string` — это **не массив символов**. Это маленький заголовок из двух полей (16 байт на 64-bit):

```
string header (на стеке или в heap):
┌─────────────┐
│  ptr *byte  │  ← указатель на байты (UTF-8)
│  len int    │  ← длина в БАЙТАХ
└─────────────┘
       │
       ↓
  байты (read-only сегмент или heap):
  [h | e | l | l | o]
```

```go
s := "hello"
// ptr → [104 101 108 108 111]
// len = 5

fmt.Println(len(s))  // 5
```

Сравните со slice (`{ptr, len, cap}`, 24 байта): у строки **нет cap** — её нельзя дорастить, потому что её нельзя менять.

**Ключевые следствия:**
- присваивание `s2 := s` копирует только заголовок (16 байт) — оба указывают на одни байты, копии данных нет
- передача строки в функцию дёшева: копируется заголовок, не содержимое
- строковые литералы лежат в read-only сегменте бинарника; несколько одинаковых литералов могут делить одну память

## Immutability: почему строку нельзя менять

Байты строки **неизменяемы**. Это не соглашение, а гарантия рантайма:

```go
s := "hello"
s[0] = 'H'   // ❌ ошибка компиляции: cannot assign to s[0]
```

Почему так важно:
- строку можно безопасно шарить между горутинами без копий и блокировок — гонок по данным быть не может
- строку-литерал можно держать в read-only памяти
- map с ключом-строкой не «сломается», если кто-то изменит исходную переменную

«Изменение» строки — это всегда создание новой:

```go
s := "hello"
s = "H" + s[1:]   // новая строка "Hello", старые байты не тронуты
```

Чтобы реально менять байты — переводи в `[]byte`, правь, конвертируй обратно (две копии):

```go
b := []byte(s)   // копия №1
b[0] = 'H'
s = string(b)    // копия №2
```

## byte vs rune: что это вообще

| Тип | Алиас | Размер | Что хранит |
|---|---|---|---|
| `byte` | `uint8` | 1 байт | один байт (0–255), часто ASCII-символ |
| `rune` | `int32` | 4 байта | один Unicode **code point** (U+0000…U+10FFFF) |

Строка внутри хранится как **UTF-8** — кодировка переменной длины:

```
символ   code point   байт в UTF-8
'A'      U+0041       1 байт:  41
'я'      U+044F       2 байта: D1 8F
'€'      U+20AC       3 байта: E2 82 AC
'🎉'      U+1F389      4 байта: F0 9F 8E 89
```

```go
s := "Hi, мир 🎉"
fmt.Println(len(s))                    // 14 — байты
fmt.Println(utf8.RuneCountInString(s)) // 9  — руны (символы)
```

Запомни: **byte = единица хранения, rune = единица смысла (символ).** В UTF-8 один символ — это 1–4 байта.

## len считает байты, а не символы

Самая частая ловушка:

```go
s := "привет"
fmt.Println(len(s))                    // 12, а не 6!
fmt.Println(utf8.RuneCountInString(s)) // 6
```

Каждая кириллическая буква — 2 байта в UTF-8, поэтому 6 символов = 12 байт.

Если нужна «длина в символах» — `utf8.RuneCountInString(s)` (без аллокации) либо `len([]rune(s))` (с аллокацией всего слайса рун).

> ⚠️ Даже `RuneCountInString` ≠ «число видимых символов» для эмодзи с модификаторами и комбинируемых символов. `"é"` может быть 1 руной (`U+00E9`) или 2 рунами (`e` + `U+0301` combining accent). Флаги-эмодзи — вообще пара code point'ов. Для «сколько визуальных символов» нужны **графемные кластеры** (пакет `golang.org/x/text/unicode/norm` или сторонние graphemes-библиотеки).

## Индексация s[i] возвращает byte

`s[i]` — это **байт**, а не символ:

```go
s := "héllo"        // 'é' = 2 байта
fmt.Println(s[1])         // 195 (первый байт 'é'), тип byte
fmt.Printf("%c\n", s[1])  // Ã — мусор, половина символа
fmt.Println(s[0])         // 104 = 'h'
```

Чтобы получить i-ю **руну**, простой индексацией не обойтись — нужно либо `[]rune(s)[i]`, либо итерация range, либо `utf8.DecodeRuneInString`:

```go
runes := []rune(s)
fmt.Printf("%c\n", runes[1])  // é
```

## range по строке: индекс байта + руна

`for i, r := range s` декодирует UTF-8 на лету: `i` — **индекс байта** начала символа, `r` — **руна**:

```go
s := "a£你"
for i, r := range s {
    fmt.Printf("i=%d  r=%c  (U+%04X)\n", i, r, r)
}
// i=0  r=a  (U+0061)
// i=1  r=£  (U+00A3)   ← £ занимает байты 1–2
// i=3  r=你  (U+4F60)   ← 你 занимает байты 3–5
```

Индексы скачут (0, 1, 3...), потому что символы разной байтовой ширины. Это ключевое отличие от `for i := 0; i < len(s); i++` (тот идёт по байтам):

```go
// range — по рунам:
for _, r := range s { /* r — корректная руна */ }

// классический for — по байтам (легко получить половину символа):
for i := 0; i < len(s); i++ { _ = s[i] /* byte */ }
```

При встрече невалидного UTF-8 range возвращает `utf8.RuneError` (`U+FFFD`, «�») и сдвигается на 1 байт.

## Конверсии: string ↔ []byte ↔ []rune

```go
s := "héllo"

b := []byte(s)   // байты как есть (UTF-8). len(b) == len(s)
r := []rune(s)   // декодирует в code points. len(r) == число символов

s2 := string(b)  // обратно из байтов
s3 := string(r)  // обратно из рун (кодирует в UTF-8)
```

| Конверсия | Что делает | Аллокация |
|---|---|---|
| `[]byte(s)` | копирует байты | да (новый слайс) |
| `string(b)` | копирует байты | да (новая строка) |
| `[]rune(s)` | декодирует UTF-8 → int32[] | да (обычно больше байт) |
| `string(r)` | кодирует int32[] → UTF-8 | да |

**Каждая конверсия копирует** — потому что string immutable, а слайс mutable; разделять память нельзя (иначе через слайс можно было бы изменить строку).

> Компилятор оптимизирует частные случаи без аллокации: `[]byte(s)` в `for range`, как ключ map (`m[string(b)]`), при сравнении (`string(b) == "x"`) и в аргументах некоторых функций. Но в общем случае рассчитывай на копию.

`[]rune` нужен, когда реально работаешь по символам (разворот строки, i-й символ, подсчёт). Для ASCII/байтовой обработки достаточно `[]byte` — дешевле.

## string(int) vs string(rune): ловушка vet

```go
n := 65
fmt.Println(string(n))     // "A", а не "65"!  go vet ругается
fmt.Println(string(rune(n))) // "A" — явно и без warning
fmt.Println(strconv.Itoa(n)) // "65" — то, что обычно хотят
```

`string(число)` интерпретирует число как **code point**, а не как текст числа. С Go 1.15+ `go vet` выдаёт предупреждение на `string(int)` (кроме `string(rune)` и `string(byte)`). Для «число → текст» — всегда `strconv.Itoa` / `fmt.Sprint`.

## Substring держит всю строку: memory retention

Подстрока `s[i:j]` **не копирует** байты — это новый заголовок на те же данные (как sub-slice):

```
big string (10 MB):
[................................]
                    ↑
              sub.ptr  sub.len=5
```

Из-за этого маленькая подстрока **держит весь большой массив байт живым**:

```go
func extractID(huge string) string {
    return huge[10:15]  // 5 байт, но huge (10 MB) не будет освобождён
}
```

GC не освободит исходные 10 MB, пока жива подстрока. Фикс — форсировать копию:

```go
func extractID(huge string) string {
    return strings.Clone(huge[10:15])  // Go 1.20+: явная копия 5 байт
}
// до 1.20: string([]byte(huge[10:15]))
```

Та же механика, что у sub-slice в [04-slices](./04-slices.md#memory-retention-скрытая-утечка) — но для строк особенно коварна, потому что подстроки берут постоянно (парсинг логов, токенов, заголовков).

## Конкатенация в цикле: O(n²) vs strings.Builder

Строки immutable → каждый `+=` создаёт **новую** строку и копирует всё накопленное:

```go
// ❌ O(n²): на каждой итерации копируется весь префикс
s := ""
for i := 0; i < n; i++ {
    s += "x"   // аллокация + копия растущей строки каждый раз
}
```

`strings.Builder` копит байты в растущем буфере (как slice append) и отдаёт строку в конце **без копии** (через unsafe внутри):

```go
// ✅ O(n): амортизированно линейно
var sb strings.Builder
sb.Grow(n)          // опционально: заранее выделить ёмкость
for i := 0; i < n; i++ {
    sb.WriteString("x")
}
s := sb.String()    // финальная строка без копирования буфера
```

Альтернативы: `strings.Join(parts, sep)` если части уже в слайсе; `bytes.Buffer` если дальше работаешь с `[]byte`/io.Writer.

> `strings.Builder` нельзя копировать после первого Write (он защищается от копирования через проверку указателя на себя — иначе паника `illegal use of non-zero Builder copied by value`).

## Сравнение строк

Сравнение `==` / `<` идёт **побайтово** (лексикографически по UTF-8):

```go
"abc" == "abc"   // true — сравнивает len, потом байты
"a" < "b"        // true
"Z" < "a"        // true — 'Z'=90 < 'a'=97 (ASCII)
"я" < "a"        // false — кириллица в UTF-8 начинается с байт >= 0xD0
```

- `==` сначала сравнивает длины (быстрый отказ), потом память
- UTF-8 спроектирован так, что байтовый порядок == порядок code point'ов, поэтому `<` даёт корректную сортировку по Unicode для большинства задач
- но это **не** регистронезависимость и не локаль-зависимая сортировка (для «человеческой» сортировки нужен `golang.org/x/text/collate`)
- регистронезависимое сравнение: `strings.EqualFold(a, b)` (корректнее, чем `ToLower` обеих)

## unsafe-конверсии без копии

Иногда копия `[]byte ↔ string` на горячем пути неприемлема. Go 1.20+ даёт официальные `unsafe`-мостики:

```go
// []byte → string без копии (Go 1.20+)
s := unsafe.String(unsafe.SliceData(b), len(b))

// string → []byte без копии
b := unsafe.Slice(unsafe.StringData(s), len(s))
```

⚠️ Это нарушает гарантию immutability: после `unsafe.String` **нельзя** менять исходный `b`, иначе строка «поедет». А `[]byte` из строки **нельзя писать** вообще (строка может быть в read-only памяти → SIGSEGV). Использовать только когда точно понимаешь lifetime и что данные не меняются. В обычном коде — обычные конверсии.

### Загадка 1: len кириллицы

```go
s := "Go!Го!"
fmt.Println(len(s))  // ?
```

<details>
<summary>Ответ</summary>

```
8
```

`G`,`o`,`!` — по 1 байту (3). `Г`,`о` — по 2 байта (4). `!` — 1 байт. Итого 3 + 4 + 1 = 8 байт. Символов же 6.
</details>

### Загадка 2: индексация даёт байт

```go
s := "é"   // U+00E9, 2 байта: C3 A9
fmt.Println(len(s))  // ?
fmt.Println(s[0])    // ?
fmt.Printf("%c", s[0]) // ?
```

<details>
<summary>Ответ</summary>

```
2
195
Ã
```

`len` = 2 байта. `s[0]` = первый байт `0xC3` = 195. `%c` от 195 = `Ã` (руна U+00C3) — потому что мы взяли половину символа.
</details>

### Загадка 3: range vs обычный for

```go
s := "a你b"
count := 0
for range s {
    count++
}
fmt.Println(count, len(s))  // ?
```

<details>
<summary>Ответ</summary>

```
3 5
```

`range` идёт по рунам → 3 итерации (`a`, `你`, `b`). `len` = 5 байт (`你` = 3 байта). Классическая разница «символы против байтов».
</details>

### Загадка 4: разворот строки

```go
func reverse(s string) string {
    b := []byte(s)
    for i, j := 0, len(b)-1; i < j; i, j = i+1, j-1 {
        b[i], b[j] = b[j], b[i]
    }
    return string(b)
}
fmt.Println(reverse("abc"))  // ?
fmt.Println(reverse("héy"))  // ?
```

<details>
<summary>Ответ</summary>

```
cba
y??h   (битый 'é')
```

Разворот **по байтам** ломает многобайтовые символы: байты `é` (C3 A9) переставятся местами и станут невалидным UTF-8. Правильно разворачивать по рунам:

```go
func reverse(s string) string {
    r := []rune(s)
    for i, j := 0, len(r)-1; i < j; i, j = i+1, j-1 {
        r[i], r[j] = r[j], r[i]
    }
    return string(r)
}
```
</details>

### Загадка 8: strings.Trim — это набор символов, а не префикс

```go
url := "https://step.com"
fmt.Println(strings.Trim(url, "https://"))        // ?
fmt.Println(strings.TrimPrefix(url, "https://"))  // ?
```

<details>
<summary>Ответ</summary>

```
ep.com
step.com
```

Второй аргумент `Trim` / `TrimLeft` / `TrimRight` — это **cutset, множество рун**, а не подстрока. Здесь это `{h, t, p, s, :, /}`.

`Trim` срезает с начала всё, что входит в множество, пока не встретит руну вне него: `h t t p s : / /` — и дальше `s`, `t` из «**st**ep» тоже в множестве → срезались! Остановка на `e`. Получилось `ep.com` — съели кусок полезных данных.

Чтобы убрать именно префикс/суффикс-подстроку — `strings.TrimPrefix` / `strings.TrimSuffix`. `Trim*` нужны только для «обрезать любые из этих символов с краёв» (пробелы, кавычки и т.п.).
</details>

### Загадка 9: strings.Split и пустые строки на краях

```go
fmt.Printf("%q\n", strings.Split("a,b,c", ","))  // ?
fmt.Printf("%q\n", strings.Split("", ","))        // ?
fmt.Printf("%q\n", strings.Split(",", ","))       // ?
fmt.Printf("%q\n", strings.Split("a,b,", ","))    // ?
fmt.Printf("%q\n", strings.Split("héllo", ""))    // ?
```

<details>
<summary>Ответ</summary>

```
["a" "b" "c"]      len 3
[""]               len 1   ← НЕ пустой срез!
["" ""]            len 2
["a" "b" ""]       len 3   ← хвостовой ""
["h" "é" "l" "l" "o"]      ← по рунам, не по байтам
```

Главные ловушки:
- **`Split("", sep)` → `[""]`** (длина 1, один пустой элемент), а не `[]`. Наивная проверка «раз разбили — значит элементов было сколько-то» ломается на пустом входе.
- **хвостовой разделитель** даёт пустой элемент в конце: `"a,b,"` → `["a","b",""]`. То же для ведущего.
- **`Split(s, "")`** разбивает на **руны** (UTF-8-aware), а не на байты: `é` остаётся одним элементом.

Если пустые элементы не нужны — `strings.FieldsFunc` или фильтрация; для пробелов — `strings.Fields` (схлопывает подряд идущие разделители и не даёт пустых).
</details>

### Загадка 10: roundtrip через []rune теряет байты

```go
s := "a\xffb"        // \xff — невалидный UTF-8
r := []rune(s)
s2 := string(r)
fmt.Println(len(s), len(s2))  // ?
fmt.Println(s == s2)          // ?
```

<details>
<summary>Ответ</summary>

```
3 6
false
```

`\xff` — невалидный байт UTF-8. При `[]rune(s)` он декодируется в `utf8.RuneError` (`U+FFFD`, «�»). Обратно `string(r)` кодирует `U+FFFD` в **3 байта** (`EF BF BD`), поэтому `len` вырос с 3 до 6, а строки перестали быть равны.

Вывод: `[]byte(s)` ↔ `string(b)` — **lossless** (байты как есть). А `[]rune(s)` → `string` **не round-trip-безопасен** для битого UTF-8: невалидные байты схлопываются в `�` и раздуваются. Если важна сохранность сырых байт — работай через `[]byte`, не через `[]rune`.
</details>

### Загадка 11: for i := range s — индексы скачут

```go
s := "a£你"   // £ = 2 байта, 你 = 3 байта
for i := range s {       // только индекс
    fmt.Printf("i=%d byte=%d  ", i, s[i])
}
```

<details>
<summary>Ответ</summary>

```
i=0 byte=97  i=1 byte=194  i=3 byte=228
```

Индексы идут `0, 1, 3` (не `0, 1, 2`) — это **байтовые смещения начал рун**, range пропускает байты-продолжения многобайтовых символов.

Главная ловушка: `s[i]` внутри такого цикла даёт **первый байт** руны, а не саму руну. `s[1]` = `194` = первый байт `£` (`C2`), `s[3]` = `228` = первый байт `你` (`E4`), а `%c` от них — мусор. Если нужна руна — бери её из второй переменной: `for i, r := range s`. «range дал индекс, а индексация по нему вернула байт» — типичная путаница.
</details>

### Загадка 12: string(rune) вне диапазона Unicode

```go
fmt.Println(string(rune(0x110000)))  // ?
fmt.Println(string(rune(-1)))        // ?
```

<details>
<summary>Ответ</summary>

```
�
�
```

Оба печатают `�` (`U+FFFD`, RuneError). `0x110000` — за верхней границей Unicode (`U+10FFFF`), `-1` — отрицательный code point. Конверсия `string(rune)` для невалидного code point не паникует, а молча возвращает replacement character. Поэтому валидировать руну (`utf8.ValidRune`) нужно **до** конверсии, если важно отличить «реально пришёл U+FFFD» от «был мусор».
</details>

## Interview-ready answer

**"Что такое string в Go и какие ловушки?"**

Строка — это immutable заголовок из двух полей: указатель на байты и длина в байтах. Байты хранятся в **UTF-8**, менять их нельзя — любое «изменение» создаёт новую строку.

**Главные ловушки:**

1. **`len(s)` — это байты, не символы.** `len("привет")` = 12. Число символов — `utf8.RuneCountInString` или `len([]rune(s))`.

2. **`s[i]` возвращает `byte`, не руну.** Для многобайтовых символов вернётся половина символа. i-я руна — через `[]rune(s)[i]` или range.

3. **`range` идёт по рунам, обычный `for` — по байтам.** `for i, r := range s` даёт байтовый индекс начала символа и руну; индексы скачут.

4. **Конверсии копируют.** `[]byte(s)`, `string(b)`, `[]rune(s)` — всегда аллокация (string immutable, нельзя делить память с mutable-слайсом). Компилятор оптимизирует частные случаи (`m[string(b)]`, сравнения).

5. **`string(int)` — это code point, не текст.** `string(65)` = `"A"`, а не `"65"`. `go vet` ругается. Для текста — `strconv.Itoa`.

6. **Substring держит всю строку в памяти.** `huge[10:15]` — 5 байт, но не даёт освободить весь `huge`. Fix: `strings.Clone`.

7. **Конкатенация `+=` в цикле — O(n²).** Каждая итерация копирует префикс. Нужен `strings.Builder` (или `strings.Join`).

8. **Разворот/обрезка по байтам ломает UTF-8.** Работай по рунам, когда важны символы.
