## Как пользоваться

Читать подряд не нужно. Этот файл существует, чтобы не заучивать термины: когда
в статье встречается незнакомое слово, достаточно вернуться сюда за одной
строкой расшифровки и ссылкой на подробный разбор.

Для собеседования важнее уметь объяснить механизм своими словами, чем помнить
точное английское название. Названия здесь приведены потому, что именно они
встречаются в выводе `perf`, `top`, `vmstat` и в документации.

Порядок изучения раздела описан в [README](./README.md).

## Два разных «ядра»

Русское слово «ядро» в этом разделе означает две несвязанные вещи. Это самая
частая причина путаницы при первом чтении.

| Что имеется в виду | Английский термин | Где встречается |
| --- | --- | --- |
| **Ядро операционной системы** — привилегированная часть ОС, управляющая ресурсами | `kernel` | [00 что такое ОС](./00-what-is-an-os.md), [06 процессы и потоки](./06-processes-and-threads.md), [07 планирование](./07-context-switching-and-scheduling.md) |
| **Ядро процессора** — независимый вычислительный блок внутри чипа | `core` | [01 архитектура CPU](./01-cpu-architecture.md), [03 согласованность кэшей](./03-cache-coherence-and-mesi.md), [04 атомарные операции](./04-atomics-and-memory-ordering.md) |

Простое правило при чтении: если рядом говорится о syscall, планировании или
правах — речь про ядро ОС. Если рядом говорится о кэшах, строках кэша или
«ядро 0 и ядро 1» — речь про ядра процессора.

## Процессор

| Термин | Расшифровка | Подробно |
| --- | --- | --- |
| ядро процессора (`core`) | независимый вычислительный блок: свои регистры, свои L1 и L2 | [01](./01-cpu-architecture.md) |
| логический CPU | единица планирования с точки зрения ОС. При SMT одно физическое ядро даёт два логических CPU | [01](./01-cpu-architecture.md), [07](./07-context-switching-and-scheduling.md) |
| SMT, Hyper-Threading | технология, при которой одно физическое ядро выполняет два потока, разделяя исполнительные блоки | [01](./01-cpu-architecture.md) |
| регистр | самая быстрая ячейка внутри ядра, операнд текущей инструкции | [02](./02-memory-hierarchy.md), [06](./06-processes-and-threads.md) |
| конвейер (`pipeline`) | разбиение выполнения инструкции на стадии, чтобы несколько инструкций обрабатывались одновременно | [01](./01-cpu-architecture.md) |
| простой конвейера (`stall`) | пауза, когда инструкция не может продолжить из-за незавершённой зависимости | [01](./01-cpu-architecture.md) |
| завершение инструкции (`retire`) | момент, когда результат инструкции окончательно фиксируется в архитектурном состоянии | [01](./01-cpu-architecture.md) |
| внеочередное выполнение (`out-of-order`) | выполнение независимых инструкций не в порядке программы | [01](./01-cpu-architecture.md) |
| предсказание переходов (`branch prediction`) | догадка процессора о том, куда пойдёт условный переход | [01](./01-cpu-architecture.md) |
| промах предсказания (`misprediction`) | неверная догадка: конвейер сбрасывается и наполняется заново | [01](./01-cpu-architecture.md) |
| спекулятивное выполнение | выполнение инструкций по предполагаемому пути до подтверждения условия | [01](./01-cpu-architecture.md) |
| SIMD | одна инструкция обрабатывает сразу несколько значений | [01](./01-cpu-architecture.md) |
| MMU | блок процессора, переводящий виртуальный адрес в физический | [05](./05-virtual-memory-and-paging.md) |

| IOPS | число операций ввода-вывода в секунду, ключевой показатель для случайного доступа к диску | [02](./02-memory-hierarchy.md) |

## Виртуальная память

| Термин | Расшифровка | Подробно |
| --- | --- | --- |
| адресное пространство | множество адресов, доступных в определённой системе адресации | [05](./05-virtual-memory-and-paging.md) |
| виртуальный адрес | адрес, которым пользуется программа | [05](./05-virtual-memory-and-paging.md) |
| физический адрес | адрес, который обслуживает подсистема памяти | [05](./05-virtual-memory-and-paging.md) |
| страница (`page`) | единица отображения памяти, обычно 4 КиБ | [05](./05-virtual-memory-and-paging.md) |
| таблица страниц (`page table`) | структура, задающая соответствие виртуальных страниц физическим | [05](./05-virtual-memory-and-paging.md) |
| TLB | кэш недавних переводов адресов внутри процессора | [05](./05-virtual-memory-and-paging.md) |
| ошибка страницы (`page fault`) | исключение процессора при обращении к неотображённой странице | [05](./05-virtual-memory-and-paging.md) |
| малая ошибка страницы (`minor fault`) | страницу нужно только создать или связать, диск не нужен | [05](./05-virtual-memory-and-paging.md) |
| большая ошибка страницы (`major fault`) | страницу нужно прочитать с диска, отсюда высокая задержка | [05](./05-virtual-memory-and-paging.md) |
| ленивое выделение (`demand paging`) | физическая страница выделяется при первом обращении, а не при запросе диапазона | [05](./05-virtual-memory-and-paging.md) |
| копирование при записи (`copy-on-write`, COW) | общая страница копируется только при первой попытке её изменить | [05](./05-virtual-memory-and-paging.md) |
| `mmap` | системный вызов, создающий отображение диапазона адресов на память или файл | [05](./05-virtual-memory-and-paging.md) |
| подкачка (`swap`) | вытеснение редко используемых страниц на диск при нехватке памяти | [05](./05-virtual-memory-and-paging.md) |
| большие страницы (`huge pages`) | страницы по 2 МиБ или 1 ГиБ вместо 4 КиБ, меньше промахов TLB | [05](./05-virtual-memory-and-paging.md) |
| VIRT | размер виртуального адресного пространства процесса, не равен занятой памяти | [05](./05-virtual-memory-and-paging.md) |
| RSS | объём физической памяти, реально занятой процессом | [05](./05-virtual-memory-and-paging.md) |

## Процессы, потоки и планирование

| Термин | Расшифровка | Подробно |
| --- | --- | --- |

| поток (`thread`) | независимый путь выполнения внутри процесса, со своим стеком и регистрами | [06](./06-processes-and-threads.md) |
| goroutine | задача, которую планирует Go runtime, а не ядро ОС | [06](./06-processes-and-threads.md) |
| PID, TID | идентификатор процесса и идентификатор потока | [06](./06-processes-and-threads.md) |
| `fork` | создание нового процесса как копии текущего | [06](./06-processes-and-threads.md) |
| `exec` | замена содержимого процесса другой программой | [06](./06-processes-and-threads.md) |
| `clone` | системный вызов Linux, из которого получаются и процессы, и потоки, и контейнеры | [06](./06-processes-and-threads.md) |
| пользовательский режим и режим ядра | два уровня привилегий процессора, разделяющие приложение и ядро ОС | [00](./00-what-is-an-os.md), [06](./06-processes-and-threads.md) |

| `vDSO` | механизм Linux, позволяющий получить часть данных ядра без перехода в режим ядра | [00](./00-what-is-an-os.md), [06](./06-processes-and-threads.md) |
| переключение режима (`mode switch`) | смена уровня привилегий; выполняемый поток при этом может не меняться | [07](./07-context-switching-and-scheduling.md) |
| переключение контекста (`context switch`) | смена выполняемого на CPU потока | [07](./07-context-switching-and-scheduling.md) |
| добровольное переключение | поток сам уходит с CPU, заблокировавшись на ожидании | [07](./07-context-switching-and-scheduling.md) |
| вынужденное переключение (`preemption`) | планировщик забирает CPU у готового потока | [07](./07-context-switching-and-scheduling.md) |
| очередь готовых задач (`run queue`) | задачи, которые могут выполняться и ждут CPU | [07](./07-context-switching-and-scheduling.md) |
| CFS, EEVDF | алгоритмы справедливого планирования обычных задач в Linux; EEVDF пришёл на смену CFS с ядра 6.6 | [07](./07-context-switching-and-scheduling.md) |
| `nice` | относительный вес обычной задачи при конкуренции за CPU | [07](./07-context-switching-and-scheduling.md) |
| cgroup | механизм ограничения и учёта ресурсов для группы процессов | [07](./07-context-switching-and-scheduling.md) |
| throttling | принудительная пауза cgroup, исчерпавшей свой бюджет CPU за период | [07](./07-context-switching-and-scheduling.md) |

## Конкурентность на уровне железа

| Термин | Расшифровка | Подробно |
| --- | --- | --- |
| согласованность кэшей (`cache coherence`) | аппаратный механизм, не дающий ядрам процессора видеть разные значения одного адреса | [03](./03-cache-coherence-and-mesi.md) |
| MESI | учебная модель протокола согласованности: четыре состояния строки кэша | [03](./03-cache-coherence-and-mesi.md) |
| ложное разделение данных (`false sharing`) | две независимые переменные попали в одну строку кэша и мешают друг другу | [03](./03-cache-coherence-and-mesi.md), [04](./04-atomics-and-memory-ordering.md) |
| выравнивающая вставка (`padding`) | добавление пустых байт, чтобы развести переменные по разным строкам кэша | [03](./03-cache-coherence-and-mesi.md) |
| конкуренция за ресурс (`contention`) | несколько исполнителей одновременно борются за одно значение или блокировку | [03](./03-cache-coherence-and-mesi.md), [04](./04-atomics-and-memory-ordering.md) |
| атомарная операция | операция, которую другие исполнители не могут увидеть частично выполненной | [04](./04-atomics-and-memory-ordering.md) |
| RMW (`read-modify-write`) | «прочитать, изменить, записать» как одна неделимая операция | [04](./04-atomics-and-memory-ordering.md) |
| CAS (`compare-and-swap`) | атомарная замена значения при совпадении с ожидаемым | [04](./04-atomics-and-memory-ordering.md) |
| буфер записей (`store buffer`) | очередь ожидающих записей, позволяющая ядру не ждать завершения каждой | [04](./04-atomics-and-memory-ordering.md) |
| порядок памяти (`memory ordering`) | правила о том, в каком порядке другие ядра могут наблюдать операции над разными адресами | [04](./04-atomics-and-memory-ordering.md) |
| барьер памяти (`memory barrier`, `fence`) | инструкция, ограничивающая наблюдаемый порядок операций вокруг неё | [04](./04-atomics-and-memory-ordering.md) |
| acquire и release | парные гарантии публикации данных: release публикует, acquire наблюдает | [04](./04-atomics-and-memory-ordering.md) |
| TSO | относительно строгая модель памяти x86-64 | [04](./04-atomics-and-memory-ordering.md) |

## Термины, которые легко перепутать

| Пара | В чём разница |
| --- | --- |
| ядро ОС и ядро процессора | первое — программа, управляющая ресурсами; второе — вычислительный блок в чипе |
| переключение режима и переключение контекста | первое меняет уровень привилегий, поток может остаться тем же; второе обязательно меняет выполняемый поток |
| VIRT и RSS | первое — размер зарезервированных диапазонов адресов; второе — реально занятая физическая память |
| малая и большая ошибка страницы | малая обходится без диска, большая требует чтения с диска и на порядки дороже |
| атомарность и согласованность кэшей | первая запрещает увидеть операцию частично; вторая согласует значения одного адреса между ядрами |
| согласованность кэшей и порядок памяти | первая отвечает за один адрес, второй — за соотношение операций над разными адресами |
| ложное разделение и настоящая конкуренция | в первом случае переменные логически независимы, во втором несколько исполнителей действительно меняют одно значение |
| `nice` и `cpu.max` | первое задаёт относительный вес при конкуренции, второе — жёсткий верхний предел CPU |
| процесс, поток и goroutine | процесс владеет ресурсами, поток исполняет код и планируется ядром, goroutine планируется Go runtime поверх потока |
