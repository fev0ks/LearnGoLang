# Примеры: клиент к LLM API

Минимальный HTTP-клиент к языковой модели на стандартной библиотеке. Код учебный: имена полей упрощены и не совпадают дословно ни с одним провайдером — важна структура, а не конкретный JSON.

## Файлы

- [client.go](./client.go) — сборка запроса структурой, разбор блочного ответа, проверка причины остановки, логирование расхода токенов. Разбор в [01-llm-api-anatomy.md](../01-llm-api-anatomy.md) и [03-reasoning-and-latency.md](../03-reasoning-and-latency.md).

---

## На что смотреть в коде

- запрос собирается структурой и сериализуется, а не склеивается подстановкой в шаблон;
- системная инструкция отделена от истории: внешний текст всегда идёт в сообщение пользователя;
- `firstText` ищет блок нужного типа вместо обращения к `Content[0]`;
- причина остановки `max_tokens` превращается в отдельную ошибку, хотя HTTP-статус успешный;
- в лог уходит расход токенов, включая рассуждения и попадания в кэш, — без этого причина долгого ответа не определяется;
- у HTTP-клиента свой таймаут: вызов модели не укладывается в общий таймаут сервиса;
- тело ошибки обрезается перед попаданием в лог.
