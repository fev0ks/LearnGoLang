В подборке смешаны три разных типа материалов: последовательные курсы, учебные реализации моделей и каталоги готовых примеров. Их не стоит читать подряд как одну программу. Сначала нужно выбрать цель: интегрировать готовую LLM в backend, разобраться в устройстве Transformer или найти пример конкретного агента.

Количество звёзд проверено через GitHub API 27 августа 2026 года и округлено до сотен. Это изменяемый показатель популярности, а не оценка технической точности или production-готовности.

## Как пользоваться подборкой

Для каждого репозитория отмечены четыре вещи:

- **Назначение** — какую задачу обучения он решает.
- **Формат** — курс, книга с кодом, набор notebook или каталог приложений.
- **Практическая польза** — что можно перенести в собственный проект.
- **Ограничение** — что материал не даёт или где требует дополнительной проверки.

Go-кода в подборке мало. Большинство примеров написано на Python, TypeScript или в Jupyter Notebook. Для Go/backend-разработчика полезнее переносить архитектурные идеи и контракты, а не механически переписывать код конкретного фреймворка.

## Последовательные курсы

### 1. Generative AI for Beginners by Microsoft

- **Назначение** — дать широкий вход в создание GenAI-приложений: основы LLM, prompting, RAG, агенты, безопасность и жизненный цикл приложения.
- **Формат** — 21 урок; учебные и практические главы, примеры преимущественно на Python и TypeScript, многочисленные переводы.
- **Практическая польза** — помогает собрать общий словарь и увидеть связь между API модели, поиском по данным, инструментами и пользовательским приложением.
- **Ограничение** — курс охватывает много тем, поэтому не заменяет углублённое изучение agent loop, evals или production-надежности.
- **Место в маршруте** — обзор перед [первым этапом](./learning-path/01-agent-foundations.md) или параллельно с ним.

### 4. AI Engineering from Scratch

- **Назначение** — провести от математических и ML-основ до LLM engineering, MCP, навыков и агентных систем.
- **Формат** — на момент проверки репозиторий заявляет 511 уроков, 20 фаз и примерно 329 часов; примеры есть на Python, TypeScript, Rust и Julia.
- **Практическая польза** — каждый урок строится вокруг создаваемого артефакта, поэтому материал подходит для длительной самостоятельной программы.
- **Ограничение** — объём слишком велик для линейного чтения «от корки до корки». Лучше выбрать маршрут под конкретную цель и фиксировать проверяемый результат каждого занятия.
- **Место в маршруте** — внешняя расширенная учебная программа; для текущего раздела особенно релевантны фазы про LLM engineering, agent loop и MCP.

Исходный список указывал 503 урока. Текущее README содержит 511, поэтому число в этой заметке привязано к дате проверки и может снова измениться.

### 5. Hugging Face Agents Course

- **Назначение** — последовательно объяснить агента, цикл `Think -> Act -> Observe`, инструменты, популярные фреймворки и оценку результата.
- **Формат** — четыре основных блока от введения до итогового проекта и сравнительной оценки (`benchmark`); есть практические задания и тесты.
- **Практическая польза** — даёт контролируемый путь от первого агента до автоматизированной оценки, а не только набор несвязанных демонстраций.
- **Ограничение** — примеры привязаны к Python-экосистеме и фреймворкам вроде `smolagents`, LangGraph и LlamaIndex. Их абстракции нужно отделять от общей механики агента.
- **Место в маршруте** — [этап 1](./learning-path/01-agent-foundations.md), [этап 2](./learning-path/02-cognition-context-and-tools.md) и [этап 5](./learning-path/05-production-reliability-and-safety.md).

## Внутреннее устройство моделей

### 2. LLMs from Scratch by Sebastian Raschka

- **Назначение** — показать разработку, предобучение (`pretraining`) и дообучение (`fine-tuning`) небольшой GPT-подобной модели с нуля.
- **Формат** — официальный код книги, главы в Jupyter Notebook, упражнения и пошаговые реализации на PyTorch.
- **Практическая польза** — объясняет токенизатор, embeddings, attention, блоки Transformer, обучение и instruction fine-tuning через работающий код.
- **Ограничение** — это материал про устройство и обучение модели, а не про эксплуатацию внешнего LLM API или backend-архитектуру агента.
- **Когда выбирать** — если требуется понимать, почему модель имеет context window, откуда берутся токены и что именно меняется при fine-tuning.

### 3. nanochat by Andrej Karpathy

- **Назначение** — предоставить компактный и изменяемый сквозной конвейер: токенизатор, предобучение, supervised fine-tuning, оценка, inference и chat CLI.
- **Формат** — связная Python-кодовая база без попытки быть универсальным фреймворком.
- **Практическая польза** — позволяет проследить полный жизненный цикл одной модели и экспериментировать с отдельными стадиями без огромной инфраструктуры.
- **Ограничение** — основной `speedrun` рассчитан на мощный GPU-узел. Репозиторий содержит уменьшенный сценарий для CPU и Apple Silicon, но он предназначен для знакомства с механикой, а не для получения сильной модели.
- **Цена эксперимента** — приведённые авторами оценки ниже $100 зависят от конкретного оборудования, облачного тарифа и длительности запуска; это не фиксированная стоимость.

### 11. Mathematics for Machine Learning

- **Назначение** — дать математическую базу для чтения ML-материалов: линейную алгебру, аналитическую геометрию, разложения матриц, векторный анализ, вероятность и оптимизацию.
- **Формат** — бесплатный PDF учебника, дополнительные главы и Jupyter Notebook для отдельных алгоритмов.
- **Практическая польза** — закрывает пробелы, из-за которых attention, gradient descent, PCA или распределения выглядят набором формул без механики.
- **Ограничение** — книга намеренно не является курсом по современным LLM. Она создаёт фундамент, после которого легче читать LLMs from Scratch и реализации статей.
- **Лицензия** — бесплатная доступность PDF не означает, что текст книги можно использовать как код под open-source лицензией; нужно соблюдать условия авторов и издателя.

### 12. labml.ai Deep Learning Paper Implementations

- **Назначение** — связать научные статьи с короткими, документированными реализациями на PyTorch.
- **Формат** — более 60 реализаций с пояснениями рядом с кодом: Transformers, LoRA, diffusion, GAN, reinforcement learning, optimizers и другие темы.
- **Практическая польза** — удобно разбирать одну конкретную идею после чтения статьи, например rotary embeddings, Switch Transformer или Adam.
- **Ограничение** — приоритетом является читаемость. Учебная реализация не обязана иметь оптимальную компоновку памяти, объединение вычислительных ядер (`kernel fusion`), распределённое обучение и отказоустойчивость production-системы.
- **Когда выбирать** — точечно, после появления вопроса по конкретному алгоритму; не как первый последовательный курс.

## Практические рецепты и каталоги

### 6. GenAI Agents by Nir Diamant

- **Назначение** — показать много вариантов агентных систем: от диалогового бота до сложной мультиагентной координации.
- **Формат** — более 50 руководств и Jupyter Notebook, организованных по техникам и прикладным сценариям.
- **Практическая польза** — источник альтернативных реализаций памяти, планирования, RAG, вызова инструментов и мультиагентных паттернов.
- **Ограничение** — это каталог, а не единая архитектура. Примеры используют разные фреймворки и могут иметь неодинаковую глубину production-проверок.
- **Лицензия** — GitHub API не определяет стандартную SPDX-лицензию, а README указывает собственные условия. Перед переносом кода нужно прочитать актуальный `LICENSE`, особенно для коммерческого проекта.

### 7. Awesome LLM Apps

- **Назначение** — предоставить большую коллекцию готовых приложений: начальные и сложные агенты, мультиагентные команды, MCP, память, голос и RAG.
- **Формат** — более 100 самостоятельных Python-примеров и шаблонов под разные модели и фреймворки; лицензия Apache-2.0.
- **Практическая польза** — помогает быстро выбрать pet-project, посмотреть структуру интеграции и сравнить несколько подходов к одной задаче.
- **Ограничение** — короткий запускаемый пример не доказывает production-готовность. До использования нужно отдельно проверить авторизацию, условия остановки, повторы, стоимость, evals и работу с недоверенным вводом.
- **Место в маршруте** — источник идей после [практической сборки первого агента](./learning-path/03-workshop-first-agent.md), а не замена базовым этапам.

### 8. Prompt Engineering Guide by DAIR.AI

- **Назначение** — собрать техники, статьи, лекции и notebook по prompting, context engineering, RAG и агентам.
- **Формат** — справочник с большим числом внешних ссылок и тематических разделов.
- **Практическая польза** — удобно искать объяснение конкретной техники и первичные статьи, а затем проверять подход на собственном eval-наборе.
- **Ограничение** — prompt-техника не является универсальным законом. Результат зависит от модели, версии API, данных и метрики качества.
- **Место в маршруте** — дополнительный источник для [этапа 2](./learning-path/02-cognition-context-and-tools.md); изменения prompt нужно проверять через [evals](./quality/01-evals.md).

### 9. OpenAI Cookbook

- **Назначение** — показать практические сценарии работы с OpenAI API: Responses API, tools, agents, structured outputs, evals, мультимодальность, latency и cost optimization.
- **Формат** — официальный набор статей, Python-скриптов и Jupyter Notebook; большинство примеров написано на Python.
- **Практическая польза** — хороший источник актуальной формы запроса и возможностей конкретного провайдера, которые нельзя надёжно восстановить из общей LLM-абстракции.
- **Ограничение** — cookbook дополняет, но не заменяет API Reference. Старый notebook может использовать устаревшую модель или API, поэтому перед переносом нужно сверить его дату с [официальным OpenAI Cookbook](https://developers.openai.com/cookbook) и документацией.
- **Место в маршруте** — [интеграция с LLM API](./api-integration/README.md), [этап 2](./learning-path/02-cognition-context-and-tools.md) и [этап 5](./learning-path/05-production-reliability-and-safety.md).

### 10. Claude Cookbooks

- **Назначение** — показать практические сценарии Claude API: классификацию, RAG, суммаризацию, вызов инструментов, vision, подагентов, evals, кэширование промпта и оптимизацию стоимости.
- **Формат** — официальный набор копируемых Python-рецептов и Jupyter Notebook; лицензия MIT.
- **Практическая польза** — позволяет сравнить устройство похожих сценариев у двух провайдеров и увидеть, где общая обёртка над LLM API начинает протекать.
- **Ограничение** — поля конкретного провайдера, модели и рекомендуемые API меняются. Перед использованием нужно сверяться с текущей документацией Anthropic.
- **Место в маршруте** — те же этапы, что у OpenAI Cookbook, но как независимая реализация другого провайдера.

## Рекомендуемый порядок для Go/backend-разработчика

Если цель — создавать LLM-функции и агентов поверх готовых моделей, разумен такой порядок:

1. Пройти выбранные уроки Microsoft Generative AI for Beginners, чтобы собрать общий словарь.
2. Параллельно пройти [локальный пошаговый маршрут](./learning-path/README.md), сохраняя Go как основной язык проекта.
3. Использовать Prompt Engineering Guide только для тем текущего этапа, а не читать весь справочник подряд.
4. Выбрать один сборник рецептов провайдера — OpenAI или Claude — и воспроизвести один сценарий через Go SDK или обычный HTTP-клиент.
5. Пройти Hugging Face Agents Course и отделить общую механику агента от абстракций Python-фреймворков.
6. Брать GenAI Agents и Awesome LLM Apps как каталог идей и вариантов реализации.
7. Перейти к LLMs from Scratch, nanochat, Mathematics for Machine Learning и labml.ai, если требуется глубже понимать модель, обучение или конкретный алгоритм.

AI Engineering from Scratch можно использовать как расширенную параллельную программу. Выбирать нужно конкретный путь внутри репозитория, иначе объём в сотни уроков начнёт конкурировать с практикой собственного проекта.

## Ограничения подборки

- **Популярность** — число звёзд показывает узнаваемость, но не проверяет корректность примеров.
- **Актуальность** — названия моделей, SDK и API быстро меняются; перед запуском нужно читать дату примера и официальную документацию.
- **Production-качество** — учебный notebook обычно не покрывает таймауты, повторы, авторизацию, идемпотентность, телеметрию и управление данными.
- **Язык** — Python-пример переносится в Go на уровне протокола и архитектуры, а не построчным переводом.
- **Безопасность** — клонирование популярного репозитория не делает его зависимостям доверенными; перед запуском нужно изучить команды установки, lock-файлы, секреты и сетевые действия.
- **Лицензия** — лицензия репозитория и права на отдельные книги, наборы данных, модели или внешние материалы могут различаться.

Практический критерий выбора ресурса: после одного учебного блока должен появиться проверяемый артефакт — код, тест, trace, eval-набор или архитектурное решение. Если материал только увеличивает список сохранённых ссылок, он пока не стал частью обучения.
