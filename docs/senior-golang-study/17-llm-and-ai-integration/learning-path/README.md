# Пошаговый маршрут по инженерии AI-агентов

Этот маршрут превращает публичную программу курса Balun.Courses в самостоятельный план обучения для Go/backend-разработчика. Он не пересказывает уроки курса и не заменяет их: страница задаёт последовательность тем, а здесь для каждого этапа сформулированы инженерная цель, практика, результат и критерий перехода дальше.

Сквозной проект — `Repository Health Agent`. Он получает данные о pull/merge request, issue и коммитах, а затем формирует проверяемые выводы о состоянии проекта. GitHub или GitLab выступают только источником данных: архитектура агента не должна зависеть от конкретного провайдера.

## Как проходить маршрут

Рекомендуемый темп — шесть этапов за шесть-восемь недель. Это учебное допущение, а не длительность исходного курса. На этап стоит закладывать две-три сессии: теория, реализация и разбор отказов.

Для каждого этапа порядок одинаков:

1. Прочитать основной материал и связанные статьи раздела.
2. Сформулировать контракт очередного инкремента до написания кода.
3. Реализовать один сквозной сценарий от входа до результата.
4. Добавить негативные сценарии и ограничения.
5. Зафиксировать наблюдения в `DECISIONS.md` проекта: что выбрано, какие альтернативы отвергнуты и почему.
6. Проверить критерии завершения этапа. Если они не выполнены, следующий слой только скроет текущие проблемы.

## Эволюция проекта

| Этап | Что появляется в системе | Что ещё намеренно отсутствует |
| --- | --- | --- |
| 1 | ограниченный agent loop и один read-only инструмент | память, фоновые задачи, запись во внешние системы |
| 2 | строгие схемы, несколько инструментов, выбор контекста | долгоживущее состояние и автономные изменения |
| 3 | проверенный вертикальный срез и тестовые сценарии | production-гарантии |
| 4 | state machine, персистентность, идемпотентность, HITL | мультиагентная координация |
| 5 | бюджеты, остановка, безопасность, трассировка и evals | несколько агентов |
| 6 | обоснованное разделение ролей и координация | бесконтрольная «команда агентов» |

Ограничение функциональности на ранних этапах принципиально. Если сразу добавить память, RAG, десять инструментов и несколько агентов, при ошибке будет непонятно, какой слой её создал.

## Базовая архитектура проекта

```text
HTTP/CLI request
    -> Run controller
        -> LLM client
        -> Tool registry
            -> Repository provider interface
                -> GitHub adapter или GitLab adapter
        -> Run state store
        -> Trace and metrics
    -> Structured report
```

Роли компонентов:

- `Run controller` управляет циклом, бюджетами и остановкой.
- `LLM client` скрывает транспорт конкретного провайдера, но не пытается сделать все возможности провайдеров одинаковыми.
- `Tool registry` хранит разрешённые инструменты и валидирует аргументы до выполнения.
- `Repository provider` отделяет предметные операции от GitHub/GitLab API.
- `Run state store` появляется на четвёртом этапе и хранит состояние процесса, а не бесконтрольную историю диалога.
- `Trace and metrics` делают один запуск объяснимым: видно решения модели, вызовы инструментов, время, ошибки и расход бюджета.

## Что считать готовым результатом

После маршрута разработчик должен уметь:

- объяснить, почему для задачи выбран агент, workflow или обычный код;
- проектировать ограниченный agent loop с явными stop conditions;
- получать структурированный результат и валидировать его на границе;
- проектировать узкие инструменты с авторизацией и идемпотентностью;
- разделять контекст, память и состояние процесса;
- безопасно восстанавливать запуск после сбоя;
- измерять не только техническую доступность, но и качество результата;
- обосновать, нужен ли второй агент и как будет устроена координация.

Итогом считается не эффектная демонстрация, а воспроизводимая система, для которой можно ответить на вопросы: что она сделала, почему, сколько это стоило, где остановилась и как проверить качество.

## Источник маршрута

Последовательность тем основана на публичной программе [«Инженерия AI-агентов: с нуля до запуска в prod»](https://balun.courses/courses/ai), прочитанной 20 августа 2026 года. В программу входят основы агентов, когнитивный и execution-слои, практический воркшоп, память и состояние, production-надежность, безопасность, observability, evals и мультиагентность.

Формулировки, объяснения, упражнения и критерии готовности в этом разделе подготовлены отдельно для данного репозитория. Цены, даты потока и рекламные заявления в учебный маршрут не включены, потому что они не относятся к инженерному содержанию и меняются со временем.
