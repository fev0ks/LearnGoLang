## Обзор каждого паттерна

### Два указателя (two pointers)

Суть: использовать два индекса, движущихся по массиву или списку, чтобы избежать вложенного цикла.

Типичная сложность: O(n) по времени, O(1) по памяти.

Две основные конфигурации:
- Указатели с двух концов (opposite ends) — сходятся к центру. Применяется на отсортированном массиве: левый сдвигается вправо, если сумма мала, правый влево — если велика.
- Указатели с разными скоростями (fast/slow) — fast делает два шага, slow один. Позволяет обнаружить цикл (встретились), найти середину (fast дошёл до конца) или k-й элемент с конца (разрыв между указателями равен k).

Типичные задачи: Two Sum II (sorted), 3Sum, Linked List Cycle, Middle of Linked List, Remove Nth Node From End.

### Скользящее окно (sliding window)

Суть: поддерживать окно [left, right] над массивом или строкой, расширяя его вправо и сужая слева при нарушении инварианта.

Типичная сложность: O(n) — каждый элемент входит и выходит из окна ровно один раз.

Ключевая идея: вместо того чтобы пересчитывать агрегат (сумму, частоту) с нуля при каждом сдвиге, агрегат обновляется инкрементально. Обычно нужна хеш-таблица для подсчёта частот или переменная для текущей суммы.

```go
left := 0
freq := make(map[byte]int)
result := 0
for right := 0; right < len(s); right++ {
    freq[s[right]]++
    // окно сужается, пока инвариант нарушен
    for freq[s[right]] > 1 {
        freq[s[left]]--
        left++
    }
    if right-left+1 > result {
        result = right - left + 1
    }
}
```

Типичные задачи: Longest Substring Without Repeating Characters, Minimum Window Substring, Maximum Sum Subarray of Size K.

### Бинарный поиск

Суть: каждый шаг отсекает половину пространства поиска, опираясь на монотонное свойство.

Типичная сложность: O(log n).

Ключевая идея: шаблон с инвариантом `[lo, hi)` или `[lo, hi]` — один вариант выбирается и выдерживается во всём коде. Ошибки почти всегда в граничных условиях: `<=` vs `<`, `mid+1` vs `mid`.

```go
lo, hi := 0, len(nums)-1
for lo <= hi {
    mid := lo + (hi-lo)/2
    if nums[mid] == target {
        return mid
    } else if nums[mid] < target {
        lo = mid + 1
    } else {
        hi = mid - 1
    }
}
return -1
```

Binary Search on answer: поиск идёт не в массиве, а в пространстве ответов. Условие `canDo(mid)` монотонно — при x достаточно большом всегда true, при малом — false. Граница двигается, пока не найдётся минимальный (или максимальный) допустимый x.

Типичные задачи: Search in Rotated Sorted Array, Find First and Last Position, Koko Eating Bananas, Capacity To Ship Packages.

### Деревья и графы

Суть: задачи на деревьях и графах в основе своей — задачи на обход. Выбор между DFS и BFS определяет, что удобнее поддерживать в памяти.

Типичная сложность: O(V + E) для графов, O(n) для деревьев.

DFS на дереве — рекурсия естественна. Постпорядковый обход нужен, когда результат узла зависит от детей (например, высота поддерева). Препорядковый — когда нужно передать информацию от корня вниз.

```go
func dfs(node *TreeNode) int {
    if node == nil {
        return 0
    }
    left := dfs(node.Left)
    right := dfs(node.Right)
    return 1 + max(left, right)
}
```

BFS на дереве — итеративный обход с очередью. Удобен, когда нужно работать с уровнями: на каждой итерации внешнего цикла обрабатывается ровно один уровень (размер очереди в начале итерации).

Union-Find: структура для эффективного объединения множеств и проверки принадлежности. Операции `Union` и `Find` с path compression и union by rank работают за O(α(n)) ≈ O(1).

Топологическая сортировка (алгоритм Кана): считается входящая степень каждого узла; узлы с нулевой степенью попадают в очередь, а при их обработке степень соседей уменьшается.

Типичные задачи: Maximum Depth of Binary Tree, Lowest Common Ancestor, Number of Islands, Course Schedule, Redundant Connection.

### Динамическое программирование

Суть: разбить задачу на перекрывающиеся подзадачи, запомнить результаты (memoization или tabulation) и избежать повторных вычислений.

Типичная сложность: от O(n) до O(n * m) в зависимости от количества состояний.

Два шага построения решения:
1. Определить состояние: что именно означает `dp[i]` — например, «минимальное количество монет для суммы i».
2. Записать переход: как `dp[i]` вычисляется через предыдущие состояния.

Типичные подкатегории:
- 1D DP: Fibonacci, Climbing Stairs, House Robber.
- 2D DP (строки): Longest Common Subsequence, Edit Distance.
- Knapsack: можно взять предметы с ограничением по весу.
- Interval DP: задачи на отрезках, палиндромы.

Признак применимости: если рекурсивное решение с перебором даёт правильный ответ, но не укладывается в лимит времени (TLE, Time Limit Exceeded), стоит проверить, пересчитываются ли одни и те же аргументы. Если да, помогает мемоизация.

Типичные задачи: Coin Change, Longest Increasing Subsequence, Word Break, Unique Paths, 0/1 Knapsack.

### Сортировки и куча

Суть: heap (куча) — структура данных, которая за O(log n) поддерживает доступ к минимальному (или максимальному) элементу.

Типичная сложность операций: O(log n) для push/pop, O(1) для peek.

В Go стандартная библиотека `container/heap` требует реализации интерфейса из пяти методов. На практике часто удобнее инвертировать знак для max-heap поверх min-heap реализации.

Ключевые применения:
- Top-K наибольших элементов: поддерживается min-heap размером K, и элемент больше вершины вытесняет её.
- Top-K наименьших: поддерживается max-heap размером K.
- Медиана потока: два heap — max-heap для левой половины, min-heap для правой. Размеры половин балансируются.
- Слияние K списков: по одному элементу из каждого списка кладётся в min-heap вместе с указателем на источник.

Сортировка для предобработки: если задача требует O(n log n), часто правильнее сначала отсортировать входные данные, а потом применить жадный подход или два указателя.

Типичные задачи: Kth Largest Element, Find Median from Data Stream, Merge K Sorted Lists, Task Scheduler.

### Перебор с возвратом (backtracking)

Суть: систематический перебор с отсечением (pruning) заведомо неверных ветвей.

Типичная сложность: O(n!) для перестановок, O(2^n) для подмножеств — backtracking не улучшает теоретическую сложность, но на практике отсечения резко сокращают количество проверяемых вариантов.

Шаблон: выбрать элемент, добавить в текущий путь, рекурсивно продолжить, отменить выбор (backtrack).

```go
func backtrack(start int, current []int, result *[][]int, nums []int) {
    *result = append(*result, append([]int{}, current...))
    for i := start; i < len(nums); i++ {
        current = append(current, nums[i])
        backtrack(i+1, current, result, nums)
        current = current[:len(current)-1]
    }
}
```

Отсечение (pruning): перед рекурсивным вызовом проверяется, может ли текущая ветвь вообще привести к ответу. Для задач с суммой — если накопленная сумма уже превысила целевую, дальше идти незачем.

Типичные задачи: Subsets, Permutations, Combination Sum, N-Queens, Sudoku Solver.

### Связные списки

Суть: задачи на связных списках требуют аккуратной работы с указателями. Большинство решаются in-place без дополнительной памяти.

Типичная сложность: O(n) по времени, O(1) по памяти.

Ключевые техники:
- Sentinel node (dummy head): упрощает обработку граничных случаев — не нужно отдельно обрабатывать удаление головы или вставку перед ней.
- Reverse in-place: три указателя (prev, curr, next), итеративно.
- Слияние двух отсортированных списков: сравниваются головы, меньшая присоединяется к результату, указатель сдвигается.
- Определение середины: fast/slow указатели.

```go
// reverse linked list
var prev *ListNode
curr := head
for curr != nil {
    next := curr.Next
    curr.Next = prev
    prev = curr
    curr = next
}
return prev
```

Типичные задачи: Reverse Linked List, Merge Two Sorted Lists, Reorder List, LRU Cache, Copy List with Random Pointer.

## Структура решения задачи на интервью

Следующий пятишаговый фреймворк помогает не паниковать и систематически прийти к решению.

**1. Clarify — уточнить условие**

Вопросы задаются до написания кода:
- Каков диапазон n? (от этого зависит допустимая сложность)
- Какие значения могут быть в массиве? Есть ли отрицательные числа? Дубликаты?
- Что возвращать, если входные данные пустые?
- Отсортирован ли входной массив?

Ответы на эти вопросы часто указывают на паттерн напрямую.

**2. Brute force — назвать наивное решение**

Самое простое решение и его сложность проговариваются вслух — это показывает понимание задачи. Кодировать его не нужно, достаточно описать словами: «два вложенных цикла, O(n²), явно медленно».

**3. Optimize — выбрать паттерн**

Дальше объясняется, почему наивное решение избыточно и какое наблюдение позволяет его улучшить. Опора — таблица распознавания: «массив отсортирован и нужна пара, значит два указателя». Сложность нового решения тоже называется вслух.

**4. Code — писать, проговаривая**

Код сопровождается комментарием вслух: «инициализирую два указателя с концов, в цикле проверяю сумму, если она меньше целевой — двигаю левый». Так интервьюер видит ход мысли и может подсказать при отклонении.

**5. Test — проверить на граничных случаях**

После написания кода проверяются граничные случаи:
- Пустой входной массив или nil
- Один элемент
- Дубликаты или все одинаковые значения
- Минимальное и максимальное значение n
- Уже отсортированный или обратно отсортированный массив (для сортировочных задач)

## Сигналы для оптимизации

Когда есть рабочий, но медленный вариант, следующая таблица помогает найти направление улучшения.

| Что видно в наивном решении | Что применить |
|---|---|
| Два вложенных цикла по одному массиву | Two Pointers или HashMap для поиска за O(1) |
| Линейный поиск в отсортированном массиве | Бинарный поиск |
| Рекурсия вычисляет одни и те же аргументы | Memoization (top-down DP) |
| "Лучший из K" или "K наибольших" в потоке | Heap (размером K) |
| "Все комбинации" и нет явной оптимизации | Backtracking с pruning |
| Пересчёт суммы/агрегата подмассива с нуля | Prefix Sum или Sliding Window |
| Повторяющиеся обращения к одному и тому же диапазону | Sparse Table, Segment Tree (для range queries) |
| Граф с взвешенными рёбрами, кратчайший путь | Dijkstra (неотрицательные веса) или Bellman-Ford |

### Подсказка по сложности

Ограничение на `n` в условии — это подсказка о требуемой сложности, а не деталь оформления. Обратная развёртка таблицы: увидев `n <= 20`, разумно сразу рассматривать экспоненциальный перебор, а увидев `n <= 10^6` — сразу отбрасывать всё, что хуже O(n log n).

| Допустимая сложность | Ориентировочный n |
|---|---|
| O(n!) | n <= 10 |
| O(2^n) | n <= 20 |
| O(n^2) | n <= 10^3 |
| O(n log n) | n <= 10^6 |
| O(n) | n <= 10^7 |
| O(log n) | n <= 10^18 |

## Interview-ready answer

**1. Как за минуту понять, какой паттерн применить?**

- Смотреть не на сюжет задачи, а на структуру входных данных и на то, что просят вернуть.
- Отсортированный массив плюс поиск пары — два указателя; подмассив или подстрока с ограничением — скользящее окно.
- «Сколько способов», «минимум шагов», «можно ли набрать» — динамическое программирование; «все комбинации» — перебор с возвратом.
- Ограничение на `n` подсказывает допустимую сложность: `n <= 20` разрешает экспоненциальный перебор, `n` порядка миллиона требует O(n log n) или лучше.

**2. Что даёт ограничение на `n` в условии?**

- Это прямая подсказка о требуемой сложности, а не деталь оформления.
- `n <= 10` допускает O(n!), `n <= 20` — O(2^n), `n <= 10³` — O(n²), `n <= 10⁶` — O(n log n), `n <= 10⁷` — O(n).
- Обратный ход тоже работает: увидев `n <= 10^18`, разумно искать логарифмическое решение, потому что даже прочитать столько данных невозможно.
- Ориентир опирается на порядок 10⁸ простых операций в секунду и на практике снижается из-за кэш-промахов и выделения памяти.

**3. Как объяснять решение вслух, чтобы это выглядело сильно?**

- Сначала уточняющие вопросы: диапазон `n`, отрицательные значения, дубликаты, что возвращать на пустом входе.
- Затем наивное решение и его сложность словами, без написания кода.
- Затем наблюдение, которое позволяет улучшить, с явной ссылкой на признак: «массив отсортирован и нужна пара, значит два указателя».
- В конце — проверка граничных случаев: пустой вход, один элемент, все элементы одинаковые, границы диапазона.

**4. Какие сигналы говорят, что рабочее решение можно ускорить?**

- Два вложенных цикла по одному массиву — заменяется на два указателя или хеш-таблицу.
- Линейный поиск в отсортированных данных — заменяется на бинарный.
- Рекурсия, которая вычисляет одни и те же аргументы, — добавляется мемоизация.
- Пересчёт агрегата подмассива с нуля — заменяется на префиксные суммы или скользящее окно.
- Полная сортировка ради нескольких наибольших элементов — заменяется на кучу размером K.
