В невзвешенном графе поиск в ширину минимизирует число рёбер. Во взвешенном
графе этого недостаточно: путь из десяти дешёвых рёбер может быть выгоднее
одного дорогого. Выбор алгоритма определяется не только наличием весов, но и их
диапазоном, знаком и тем, нужно ли обнаруживать отрицательные циклы.

---

## Модель взвешенного графа

Ребро хранит вершину назначения и стоимость перехода. Список смежности занимает
O(V + E) памяти и подходит для разреженных графов, типичных для backend-задач:
маршрутов, зависимостей и сетей сервисов.

```go
import (
    "container/heap"
    "container/list"
)

const infinity int64 = 1<<63 - 1

type Edge struct {
    To     int
    Weight int64
}

type WeightedGraph [][]Edge
```

В статье граф ориентированный. Для неориентированного ребра `{u, v, weight}`
нужно добавить два перехода: `u -> v` и `v -> u`.

Вес должен иметь доменный смысл: время, расстояние, цену или штраф. Смешивать в
одной сумме миллисекунды и деньги нельзя. Если критериев несколько, сначала
нужно определить функцию стоимости или использовать многокритериальный поиск.

## Как выбрать алгоритм

| Условия | Алгоритм | Время | Ключевое ограничение |
| --- | --- | --- | --- |
| Все рёбра равнозначны | BFS | O(V + E) | Минимизирует число рёбер |
| Веса только `0` и `1` | 0-1 BFS | O(V + E) | Нужен дек, а не обычная очередь |
| Все веса неотрицательны | Dijkstra | O((V + E) log V) | Отрицательные рёбра запрещены |
| Есть отрицательные рёбра | Bellman-Ford | O(VE) | Медленнее, но обнаруживает достижимый отрицательный цикл |
| Граф ацикличен | Релаксация в топологическом порядке | O(V + E) | Работает и с отрицательными весами |

Сложность Dijkstra в таблице предполагает heap с обновлением приоритета или
обычный простой граф. Реализация ниже использует более простой lazy-подход:
вместо изменения старого элемента добавляет новый. В худшем случае heap хранит
O(E) записей, поэтому строгая оценка этой реализации — O((V + E) log E).

Если все рёбра имеют один и тот же положительный вес, его можно мысленно убрать:
минимизация общей стоимости совпадает с минимизацией числа рёбер, и обычный BFS
проще Dijkstra.

## Алгоритм Дейкстры

Алгоритм хранит лучшую известную дистанцию до каждой вершины. На каждом шаге
min-heap отдаёт вершину с минимальной текущей дистанцией, после чего исходящие
рёбра релаксируются: проверяется, улучшит ли путь через эту вершину ответ для
соседа.

Стандартный [`container/heap`](https://pkg.go.dev/container/heap) не предоставляет
готовую priority queue, поэтому сначала реализуется его интерфейс.

```go
type pathItem struct {
    Vertex   int
    Distance int64
}

type minPathHeap []pathItem

func (h minPathHeap) Len() int           { return len(h) }
func (h minPathHeap) Less(i, j int) bool { return h[i].Distance < h[j].Distance }
func (h minPathHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *minPathHeap) Push(value any) {
    *h = append(*h, value.(pathItem))
}

func (h *minPathHeap) Pop() any {
    old := *h
    last := len(old) - 1
    value := old[last]
    old[last] = pathItem{}
    *h = old[:last]
    return value
}
```

До запуска проверяются индексы вершин и неотрицательность весов. Это часть
контракта алгоритма, а не необязательная защита от плохого ввода.

```go
func validateNonNegativeGraph(graph WeightedGraph) bool {
    for _, edges := range graph {
        for _, edge := range edges {
            if edge.To < 0 || edge.To >= len(graph) || edge.Weight < 0 {
                return false
            }
        }
    }
    return true
}

func Dijkstra(graph WeightedGraph, start int) ([]int64, []int, bool) {
    if start < 0 || start >= len(graph) || !validateNonNegativeGraph(graph) {
        return nil, nil, false
    }

    distances := make([]int64, len(graph))
    parents := make([]int, len(graph))
    for vertex := range graph {
        distances[vertex] = infinity
        parents[vertex] = -1
    }
    distances[start] = 0

    queue := minPathHeap{{Vertex: start, Distance: 0}}
    heap.Init(&queue)

    for queue.Len() > 0 {
        current := heap.Pop(&queue).(pathItem)
        if current.Distance != distances[current.Vertex] {
            continue // устаревшая запись после более успешной релаксации
        }

        for _, edge := range graph[current.Vertex] {
            if current.Distance > infinity-edge.Weight {
                return nil, nil, false // сумма не помещается в int64
            }
            candidate := current.Distance + edge.Weight
            if candidate >= distances[edge.To] {
                continue
            }

            distances[edge.To] = candidate
            parents[edge.To] = current.Vertex
            heap.Push(&queue, pathItem{
                Vertex:   edge.To,
                Distance: candidate,
            })
        }
    }

    return distances, parents, true
}
```

`infinity` означает «вершина пока недостижима». Проверка перед сложением нужна:
иначе большое расстояние и вес могут переполнить `int64`, стать отрицательным
числом и выглядеть как лучший путь.

Рассмотрим граф:

```text
0 -> 1 (4)
0 -> 2 (1)
2 -> 1 (2)
1 -> 3 (1)
2 -> 3 (5)
```

Ход релаксаций от вершины `0`:

| Извлечённая вершина | Изменившиеся расстояния |
| --- | --- |
| `0`, дистанция `0` | `d[1] = 4`, `d[2] = 1` |
| `2`, дистанция `1` | `d[1] = 3`, `d[3] = 6` |
| `1`, дистанция `3` | `d[3] = 4` |
| `1`, дистанция `4` | запись устарела и пропускается |
| `3`, дистанция `4` | улучшений нет |

Итоговые дистанции: `[0, 3, 1, 4]`. Кратчайший путь к `3` проходит как
`0 -> 2 -> 1 -> 3` и стоит `1 + 2 + 1 = 4`.

## Почему Дейкстра работает

Когда из heap извлечена минимальная актуальная дистанция `d[v]`, любой другой
нерассмотренный путь сначала должен прийти в вершину с дистанцией не меньше
`d[v]`. Неотрицательное следующее ребро не сможет уменьшить сумму. Поэтому
`d[v]` уже оптимальна.

Именно здесь используется запрет отрицательных весов. При отрицательном ребре
более дорогой префикс пути способен позже резко уменьшить общую стоимость, и
ранняя фиксация вершины становится неверной.

Lazy-реализация не удаляет старую запись вершины при улучшении дистанции. В heap
могут одновременно находиться `(vertex=1, distance=4)` и
`(vertex=1, distance=3)`. Сравнение с `distances[current.Vertex]` отличает
актуальную запись от устаревшей.

Раннее завершение при поиске одной цели допустимо только когда эта цель
извлечена из heap с актуальной минимальной дистанцией. Остановиться в момент
первого обнаружения соседа нельзя: позже может найтись более дешёвый путь.

## Восстановление пути

Одной дистанции недостаточно, если нужно вернуть маршрут. При каждой успешной
релаксации код выше записывает предка `parents[to] = current`. Затем путь
собирается от цели к старту и разворачивается.

```go
func RestorePath(parents []int, start, target int) ([]int, bool) {
    if start < 0 || start >= len(parents) ||
        target < 0 || target >= len(parents) {
        return nil, false
    }

    reversed := make([]int, 0)
    current := target
    for steps := 0; current != -1 && steps < len(parents); steps++ {
        if current < 0 || current >= len(parents) {
            return nil, false
        }
        reversed = append(reversed, current)
        if current == start {
            for left, right := 0, len(reversed)-1; left < right; left, right = left+1, right-1 {
                reversed[left], reversed[right] = reversed[right], reversed[left]
            }
            return reversed, true
        }
        current = parents[current]
    }

    return nil, false
}
```

Ограничение числа шагов и проверка индекса защищают функцию от цикла или
некорректной ссылки в повреждённом массиве предков. Для результата Dijkstra они
появиться не должны. У недостижимой цели предок останется `-1`, и функция
вернёт `false`.

При нескольких кратчайших путях код возвращает один из них. Если нужен
детерминированный выбор, например лексикографически минимальный маршрут, правило
разрешения равенства должно быть частью алгоритма и тестов.

## 0-1 BFS

Если веса равны только `0` или `1`, heap избыточен. Дек поддерживает тот же
порядок обработки: переход стоимости `0` кладётся в начало, а стоимости `1` —
в конец.

```go
func validateZeroOneGraph(graph WeightedGraph) bool {
    for _, edges := range graph {
        for _, edge := range edges {
            if edge.To < 0 || edge.To >= len(graph) ||
                (edge.Weight != 0 && edge.Weight != 1) {
                return false
            }
        }
    }
    return true
}

func ZeroOneBFS(graph WeightedGraph, start int) ([]int64, bool) {
    if start < 0 || start >= len(graph) || !validateZeroOneGraph(graph) {
        return nil, false
    }

    distances := make([]int64, len(graph))
    processed := make([]bool, len(graph))
    for vertex := range graph {
        distances[vertex] = infinity
    }
    distances[start] = 0

    deque := list.New()
    deque.PushFront(start)

    for deque.Len() > 0 {
        front := deque.Front()
        vertex := front.Value.(int)
        deque.Remove(front)
        if processed[vertex] {
            continue
        }
        processed[vertex] = true

        for _, edge := range graph[vertex] {
            candidate := distances[vertex] + edge.Weight
            if candidate >= distances[edge.To] {
                continue
            }

            distances[edge.To] = candidate
            if edge.Weight == 0 {
                deque.PushFront(edge.To)
            } else {
                deque.PushBack(edge.To)
            }
        }
    }

    return distances, true
}
```

В начале дека остаются вершины с текущей дистанцией, в конце — кандидаты на
следующий уровень стоимости. Поэтому вершины извлекаются в неубывающем порядке,
как в Dijkstra, но каждая операция с деком стоит O(1). Итоговая сложность —
O(V + E) по времени и O(V) по дополнительной памяти.

Типичный пример — граф, где обычный переход бесплатен, а смена режима стоит
одну единицу. Если веса `0` и `2`, напрямую применять 0-1 BFS уже нельзя.

## Отрицательные веса и Bellman-Ford

Контрпример для Dijkstra:

```text
0 -> A (2)
0 -> B (5)
B -> A (-10)
```

Сначала вершина `A` выглядит достижимой за `2`, но путь `0 -> B -> A` стоит
`-5`. Реализация Dijkstra, которая окончательно помечает `A` обработанной,
получит неверный ответ. Версия без такой отметки тоже теряет доказательство
сложности и может не завершиться при достижимом отрицательном цикле.

Bellman-Ford до `V - 1` раз проходит по всем рёбрам и выполняет релаксации. Любой
простой путь содержит не больше `V - 1` рёбер, поэтому после этих проходов все
конечные кратчайшие пути найдены. Если на дополнительном проходе расстояние ещё
улучшается, из старта достижим отрицательный цикл.

Важна формулировка «достижим из старта». Цикл в отдельной компоненте не влияет
на пути из выбранной вершины и обычный запуск его не обнаружит. Для поиска
любого отрицательного цикла можно добавить искусственный источник с нулевыми
рёбрами во все вершины.

Если граф является DAG, Bellman-Ford не нужен: после топологической сортировки
каждое ребро достаточно релаксировать один раз. Это даёт O(V + E) даже при
отрицательных весах, потому что циклов в графе нет.

## Практические ограничения

- **Снимок весов.** Dijkstra предполагает, что веса не меняются во время
  вычисления. Если latency рёбер обновляется параллельно, ответ относится к
  несогласованному снимку или требует версионирования графа.
- **Время как вес.** В сети стоимость перехода может зависеть от момента входа
  в ребро. Обычный Dijkstra корректен не для любой time-dependent модели;
  нужны дополнительные условия, например невозможность выиграть за счёт более
  позднего старта, или специализированный алгоритм.
- **Размер heap.** Lazy-подход проще decrease-key, но может накопить O(E)
  элементов. На большом графе это заметный memory trade-off.
- **Тип числа.** Максимальная длина пути должна помещаться в выбранный тип.
  Проверять нужно сумму пути, а не только отдельный вес.
- **Направление рёбер.** Дорожный или сетевой маршрут не обязательно симметричен.
  Автоматическое добавление обратного ребра может изменить задачу.
- **Одна цель.** При поиске пути до единственной цели можно завершиться после её
  актуального извлечения из heap и не обходить оставшийся граф.
- **Распределённая система.** Алгоритм в памяти не решает доставку обновлений,
  консистентность topology snapshot и отказ узла. Это отдельные operational
  свойства системы маршрутизации.

## Типичные ошибки

- Запускать Dijkstra при наличии хотя бы одного отрицательного ребра.
- Использовать BFS на графе с разными весами и минимизировать число переходов
  вместо стоимости.
- Применять 0-1 BFS к весам вне множества `{0, 1}`.
- Не пропускать устаревшие записи в lazy heap и многократно обрабатывать одну
  вершину.
- Завершать поиск, когда целевая вершина впервые добавлена в heap, а не когда
  извлечена с актуальной дистанцией.
- Складывать расстояния без проверки переполнения.
- Возвращать `infinity` как обычное расстояние и не объяснять недостижимость.
- Забывать массив предков, когда по контракту нужен сам маршрут, а не только его
  стоимость.
- Называть любую O((V + E) log V) реализацию Dijkstra линейной на разреженном
  графе: логарифмический множитель никуда не исчезает.

## Interview-ready answer

**1. Как выбрать алгоритм кратчайшего пути?**

- Без весов — BFS минимизирует число рёбер за O(V + E).
- Веса `0/1` — 0-1 BFS с деком сохраняет O(V + E).
- Неотрицательные веса — Dijkstra с min-heap.
- Отрицательные рёбра — Bellman-Ford или линейная релаксация, если граф является DAG.

**2. Почему Dijkstra запрещает отрицательные веса?**

- Инвариант — извлечённая минимальная дистанция считается окончательной.
- Неотрицательность — продолжение любого более дорогого пути не может сделать
  его дешевле уже найденного.
- Нарушение — отрицательное ребро способно позже улучшить уже обработанную вершину.

**3. Зачем lazy Dijkstra хранит несколько записей одной вершины?**

- Ограничение API — стандартный heap не обновляет произвольный приоритет без
  дополнительного индекса.
- Упрощение — улучшенная дистанция добавляется как новая запись.
- Фильтр — при извлечении запись сравнивается с текущей дистанцией; старая
  пропускается.
- Trade-off — код проще, но heap может занимать O(E) памяти.

**4. Чем 0-1 BFS отличается от обычного BFS?**

- Структура — используется дек вместо FIFO-очереди.
- Нулевое ребро — сосед добавляется в начало и обрабатывается с тем же уровнем стоимости.
- Единичное ребро — сосед добавляется в конец как следующий уровень.
- Граница — корректность и линейная сложность требуют весов только `0` и `1`.

**5. Как восстановить кратчайший путь?**

- Релаксация — при улучшении `distance[to]` запоминается `parent[to] = from`.
- Сборка — после завершения поиск идёт от цели по предкам до старта.
- Порядок — полученная последовательность разворачивается.
- Недостижимость — если цепочка не пришла к старту, маршрута нет.
