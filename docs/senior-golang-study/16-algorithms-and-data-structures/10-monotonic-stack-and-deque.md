Монотонная структура хранит не все просмотренные элементы, а только кандидатов,
которые ещё могут стать ответом. Новый элемент удаляет кандидатов, заведомо
хуже него. Такой принцип превращает повторный поиск максимума, минимума или
ближайшей границы из квадратичного прохода в линейный.

---

## Ментальная модель

Обычный стек определяет только порядок доступа LIFO. Монотонный стек добавляет
инвариант порядка значений, например от больших к меньшим. Если новый элемент
нарушает инвариант, элементы снимаются со стека, пока порядок не восстановится.

Стек обычно хранит индексы, а не сами значения. Индекс даёт сразу три вещи:

- значение через `nums[index]`;
- расстояние `current-index`;
- возможность проверить, вышел ли элемент за границу окна.

Направление монотонности выбирается от вопроса:

| Что нужно найти | Кандидаты в структуре | Когда снимать |
| --- | --- | --- |
| Следующий строго больший | значения не возрастают | новый элемент строго больше вершины |
| Следующий больший или равный | значения убывают | новый элемент больше или равен вершине |
| Следующий строго меньший | значения не убывают | новый элемент строго меньше вершины |
| Максимум окна | значения убывают от начала дека | новый элемент не меньше хвоста |

Фразы «возрастающий стек» и «стек для следующего большего» могут описывать
разные направления обхода. Надёжнее проговаривать точный инвариант значений от
дна к вершине и условие снятия.

## Следующий больший элемент

Для каждого элемента нужно найти первый индекс справа со строго большим
значением. Наивный поиск вправо для каждого индекса стоит O(n²).

Стек хранит индексы, для которых ответ ещё не найден. Значения на этих индексах
не возрастают от дна к вершине. Когда приходит большее значение, оно становится
ответом для всех меньших элементов на вершине.

```go
// NextGreaterIndices возвращает индекс первого строго большего элемента справа.
// Если такого элемента нет, результат для позиции равен -1.
func NextGreaterIndices(nums []int) []int {
    result := make([]int, len(nums))
    for i := range result {
        result[i] = -1
    }

    stack := make([]int, 0, len(nums))
    for i, value := range nums {
        for len(stack) > 0 && nums[stack[len(stack)-1]] < value {
            index := stack[len(stack)-1]
            stack = stack[:len(stack)-1]
            result[index] = i
        }
        stack = append(stack, i)
    }

    return result
}
```

Для `nums = [2, 1, 2, 4, 3]` результат равен `[3, 2, 3, -1, -1]`:

```text
index 0, value 2 -> index 3, value 4
index 1, value 1 -> index 2, value 2
index 2, value 2 -> index 3, value 4
index 3, value 4 -> справа нет большего
index 4, value 3 -> справа нет большего
```

Равные двойки не снимают друг друга, потому что задача требует строго большее
значение. Замена `<` на `<=` изменила бы контракт на «больший или равный».

## Почему вложенный цикл остаётся линейным

Внутри основного цикла есть `for`, но один индекс проходит только два изменения
состояния:

1. Один раз добавляется в стек.
2. Не более одного раза снимается со стека.

Для `n` индексов получается не более `n` добавлений и `n` снятий. Суммарно это
до `2n` стековых операций, то есть O(n) времени. Отдельная итерация может снять
много элементов, но эти элементы больше никогда не вернутся в структуру.

Это амортизационный анализ, аналогичный объяснению линейной сложности
скользящего окна: оценивается суммарное движение границ, а не один внешний шаг.

## Максимальный прямоугольник в гистограмме

Высоты столбцов неотрицательны. Для каждого столбца нужно узнать, как далеко
его высота может продолжаться влево и вправо, пока не встретится меньший
столбец. Монотонный стек хранит индексы столбцов с неубывающими высотами.

Когда приходит меньшая высота, прямоугольник для снятого столбца уже нельзя
продлить вправо. Правая граница равна текущему индексу, левая — новой вершине
стека после снятия.

```go
// LargestRectangleArea возвращает максимальную площадь.
// Предусловие: все heights неотрицательны.
func LargestRectangleArea(heights []int) int64 {
    stack := make([]int, 0, len(heights))
    var best int64

    for i := 0; i <= len(heights); i++ {
        current := 0 // виртуальный нулевой столбец снимает остаток стека
        if i < len(heights) {
            current = heights[i]
        }

        for len(stack) > 0 && heights[stack[len(stack)-1]] > current {
            index := stack[len(stack)-1]
            stack = stack[:len(stack)-1]

            left := -1
            if len(stack) > 0 {
                left = stack[len(stack)-1]
            }
            width := i - left - 1
            area := int64(heights[index]) * int64(width)
            if area > best {
                best = area
            }
        }

        if i < len(heights) {
            stack = append(stack, i)
        }
    }

    return best
}
```

На входе `[2, 1, 5, 6, 2, 3]` при индексе `4` приходит высота `2`:

```text
снимаем height=6: width=1, area=6
снимаем height=5: width=2, area=10
```

Максимум равен `10`. Виртуальный столбец в конце нужен, потому что для
возрастающего суффикса справа не появится естественной меньшей высоты.

Площадь вычисляется в `int64`, чтобы результат не зависел от разрядности `int`.
Контракт всё равно должен ограничивать произведение
`maxHeight * len(heights)`: сам `int64` тоже может переполниться.

## Максимум скользящего окна

Для окна размера `k` стек недостаточен: элементы нужно удалять и с одного
конца по возрасту, и с другого по значению. Поэтому используется двусторонняя
очередь — дек (`deque`).

Дек хранит индексы в двух порядках:

- индексы возрастают от начала к концу;
- значения убывают, поэтому первый индекс всегда указывает на максимум окна.

```go
// MaxSlidingWindow возвращает максимум каждого окна длиной k.
func MaxSlidingWindow(nums []int, k int) ([]int, bool) {
    if k <= 0 || k > len(nums) {
        return nil, false
    }

    result := make([]int, 0, len(nums)-k+1)
    deque := make([]int, 0, k)

    for i, value := range nums {
        // Индексы слева уже не принадлежат [i-k+1, i].
        for len(deque) > 0 && deque[0] <= i-k {
            deque = deque[1:]
        }

        // Более старый элемент с меньшим или равным значением уже не победит.
        for len(deque) > 0 && nums[deque[len(deque)-1]] <= value {
            deque = deque[:len(deque)-1]
        }

        deque = append(deque, i)
        if i >= k-1 {
            result = append(result, nums[deque[0]])
        }
    }

    return result, true
}
```

Для `[1, 3, -1, -3, 5, 3, 6, 7]` и `k = 3` ответ равен
`[3, 3, 5, 5, 6, 7]`.

Каждый индекс добавляется и удаляется не более одного раза, поэтому время O(n),
а живая длина дека не превышает `k`. Срез хранит `int`, поэтому удалённые
индексы не удерживают объекты от GC. Для дека указателей хвостовые и головные
слоты нужно обнулять либо использовать кольцевой буфер.

## Стек, дек или куча

| Требование | Структура | Время | Память |
| --- | --- | --- | --- |
| Ближайший больший или меньший элемент | Монотонный стек | O(n) за весь проход | O(n) |
| Максимум или минимум движущегося окна | Монотонный дек | O(n) за весь проход | O(k) |
| Экстремум при произвольных вставках и удалениях | Куча | O(log n) на изменение | O(n) |
| Top-K без требования ближайшей позиции | Куча размером K | O(n log k) | O(k) |

Монотонная структура выигрывает за счёт более сильного ограничения: элементы
приходят в известном порядке, а удалённый кандидат никогда не понадобится
снова. Если удаление произвольно или нужно вернуть кандидата после отмены
операции, куча либо сбалансированное дерево подходит лучше.

## Дубликаты и строгие сравнения

Знак сравнения является частью контракта алгоритма:

- `<` снимает элемент только при строго большем новом значении;
- `<=` также снимает равный элемент и обычно оставляет более новый индекс;
- `>` ищет строго меньшую границу;
- `>=` объединяет равные высоты или значения согласно выбранной модели.

В максимуме окна равный новый элемент вытесняет старый: он не меньше и выйдет
из окна позже. В задаче о следующем строго большем равные элементы должны
остаться, потому что не являются ответом друг для друга.

Для гистограммы допустимы несколько корректных соглашений о равных высотах, но
формулы левой и правой границ должны соответствовать одному соглашению. Смена
`>` на `>=` без повторного доказательства часто даёт неправильную ширину.

## Практические ограничения

- **Потоковый максимум.** Монотонный дек подходит для одного процесса и окна,
  заданного порядком событий. Поздние события и распределённое состояние
  требуют отдельной политики watermark и переупорядочивания.
- **Память среза.** Операция `deque = deque[1:]` работает за O(1), но для
  долгоживущей очереди удобнее кольцевой буфер, который переиспользует
  фиксированную память.
- **Индексы против значений.** Хранение только значений теряет возраст элемента
  и не позволяет понять, вышел ли он из окна.
- **Несколько метрик.** Отдельный дек нужен для каждого независимого агрегата.
  Для ad hoc запросов по произвольным диапазонам лучше дерево диапазонов или
  предварительно рассчитанная структура.
- **Проверка производительности.** Дек убирает логарифм кучи, но на маленьком
  `k` и коротком входе разница может быть меньше стоимости более сложного кода.

---

## Типичные ошибки

- Хранить значения, когда для ответа нужны расстояние или срок жизни в окне.
- Перепутать возрастающий порядок значений с задачей «следующий больший».
- Использовать `<=` вместо `<` и незаметно изменить строгий контракт.
- Помечать вложенный `for` как O(n²), не посчитав число добавлений и удалений.
- Не добавить виртуальную границу и оставить элементы в стеке гистограммы.
- Вычислять ширину до снятия вершины или использовать снятый индекс как левую
  границу вместо новой вершины стека.
- Удалять хвост дека по значению, но не удалять начало по возрасту.
- Не проверять `k <= 0` и `k > len(nums)`.

## Interview-ready answer

**1. Что хранит монотонный стек?**

- Суть — индексы кандидатов, для которых ответ ещё не найден.
- Инвариант — значения по индексам идут в заранее выбранном монотонном порядке.
- Удаление — новый элемент снимает кандидатов, которые больше не могут стать ответом.

**2. Почему алгоритм со вложенным циклом работает за O(n)?**

- Добавление — каждый индекс попадает в структуру один раз.
- Удаление — каждый индекс снимается не более одного раза.
- Итог — не более `2n` изменений структуры дают O(n) амортизированного времени.

**3. Зачем хранить индексы, а не значения?**

- Значение — доступно как `nums[index]`.
- Расстояние — вычисляется разностью текущего и сохранённого индексов.
- Срок жизни — индекс показывает, вышел ли элемент из скользящего окна.

**4. Чем монотонный дек отличается от кучи для максимума окна?**

- Дек — удаляет заведомо слабых кандидатов и обрабатывает весь поток за O(n).
- Куча — поддерживает максимум за O(log k) на элемент и требует ленивого удаления устаревших индексов.
- Ограничение дека — порядок поступления и удаления должен совпадать с движением окна.

**5. Почему сравнение `<` или `<=` нельзя выбирать механически?**

- Контракт — знак определяет, считается ли равный элемент ответом.
- Возраст — в деке равный новый элемент обычно выгоднее старого, потому что позже выйдет из окна.
- Границы — в гистограмме выбор строгости меняет ширину прямоугольника и требует согласованных формул.
