Задачи об интервалах становятся сложными не из-за сортировки, а из-за
неопределённых границ. Сначала нужно решить, включается ли момент окончания,
считаются ли соседние интервалы пересекающимися и можно ли объединять пустые
диапазоны. После этого большинство решений сводится к сортировке и одному
линейному проходу.

---

## Сначала определить границы

В статье используется полуинтервал `[start, end)`: начало включено, окончание
не включено. Такая модель совпадает со срезами Go и удобна для времени:

```text
[10:00, 11:00) и [11:00, 12:00) не пересекаются
```

Первый ресурс освобождается ровно в 11:00, второй занимает его с 11:00.
Пустой интервал `[x, x)` не содержит ни одной точки и обычно отбрасывается.

```go
import (
    "cmp"
    "slices"
)

type Interval struct {
    Start int
    End   int // не включается
}

func validInterval(interval Interval) bool {
    return interval.Start <= interval.End
}
```

Закрытая модель `[start, end]` имеет другой контракт: интервалы `[1, 3]` и
`[3, 5]` пересекаются в точке `3`. Нельзя перенести условие сравнения из одной
модели в другую без изменения результата.

Для времени те же правила выражаются через `time.Time`. Разность времён не
нужна для сортировки: сравнение через `Before` и `Equal` не переполняется и
лучше показывает смысл.

## Слияние интервалов

После сортировки по началу все интервалы, способные пересечь текущий
объединённый диапазон, расположены подряд. Достаточно сравнивать следующий
интервал с последним результатом.

Флаг `mergeAdjacent` явно задаёт, нужно ли склеивать соседние `[1, 3)` и
`[3, 5)`. По умолчанию они не пересекаются, но в задачах про покрытие их часто
удобно объединить.

```go
// MergeIntervals не меняет входной срез.
func MergeIntervals(intervals []Interval, mergeAdjacent bool) ([]Interval, bool) {
    sorted := make([]Interval, 0, len(intervals))
    for _, interval := range intervals {
        if !validInterval(interval) {
            return nil, false
        }
        if interval.Start == interval.End {
            continue // пустой полуинтервал ничего не покрывает
        }
        sorted = append(sorted, interval)
    }

    slices.SortFunc(sorted, func(a, b Interval) int {
        if byStart := cmp.Compare(a.Start, b.Start); byStart != 0 {
            return byStart
        }
        return cmp.Compare(a.End, b.End)
    })

    result := make([]Interval, 0, len(sorted))
    for _, next := range sorted {
        if len(result) == 0 {
            result = append(result, next)
            continue
        }

        last := &result[len(result)-1]
        overlaps := next.Start < last.End
        if mergeAdjacent {
            overlaps = next.Start <= last.End
        }

        if !overlaps {
            result = append(result, next)
            continue
        }
        if next.End > last.End {
            last.End = next.End
        }
    }

    return result, true
}
```

Пример:

```text
input: [1,3), [2,5), [5,7)

mergeAdjacent=false -> [1,5), [5,7)
mergeAdjacent=true  -> [1,7)
```

Сортировка стоит O(n log n), проход O(n), дополнительная память O(n), потому
что функция сохраняет входной порядок вызывающего кода. Если вход можно менять,
сортировка in-place убирает копию, но побочный эффект нужно зафиксировать в API.

## Пересечение двух списков интервалов

Если оба списка уже отсортированы и внутри каждого интервалы не пересекаются,
достаточно двух указателей. Пересечение текущей пары равно:

```text
start = max(a.Start, b.Start)
end   = min(a.End, b.End)
```

Оно непусто только при `start < end`. Затем указатель интервала, который
заканчивается раньше, можно безвозвратно сдвинуть: он уже не пересечётся ни с
одним более поздним интервалом другого списка.

```go
func IntersectIntervals(first, second []Interval) ([]Interval, bool) {
    if !sortedAndDisjoint(first) || !sortedAndDisjoint(second) {
        return nil, false
    }

    result := make([]Interval, 0)
    i, j := 0, 0

    for i < len(first) && j < len(second) {
        start := max(first[i].Start, second[j].Start)
        end := min(first[i].End, second[j].End)
        if start < end {
            result = append(result, Interval{Start: start, End: end})
        }

        switch {
        case first[i].End < second[j].End:
            i++
        case first[i].End > second[j].End:
            j++
        default:
            i++
            j++
        }
    }

    return result, true
}

func sortedAndDisjoint(intervals []Interval) bool {
    for i, interval := range intervals {
        if !validInterval(interval) {
            return false
        }
        if i > 0 && intervals[i-1].End > interval.Start {
            return false
        }
    }
    return true
}
```

Время O(n + m), не считая возвращаемого результата память O(1). Если списки не
отсортированы или содержат внутренние пересечения, сначала их нужно нормализовать
через слияние.

## Максимальное число одновременных интервалов

Задача формулируется как «сколько ресурсов нужно, чтобы обслужить все интервалы
без ожидания». Каждое начало добавляет один занятый ресурс, каждое окончание
освобождает один.

```go
type boundaryEvent struct {
    Position int
    Delta    int
}

func MaxConcurrent(intervals []Interval) (int, bool) {
    events := make([]boundaryEvent, 0, 2*len(intervals))
    for _, interval := range intervals {
        if !validInterval(interval) {
            return 0, false
        }
        if interval.Start == interval.End {
            continue
        }
        events = append(events,
            boundaryEvent{Position: interval.Start, Delta: 1},
            boundaryEvent{Position: interval.End, Delta: -1},
        )
    }

    slices.SortFunc(events, func(a, b boundaryEvent) int {
        if byPosition := cmp.Compare(a.Position, b.Position); byPosition != 0 {
            return byPosition
        }
        // Для [start, end) окончание обрабатывается раньше начала в той же точке.
        return cmp.Compare(a.Delta, b.Delta)
    })

    current, best := 0, 0
    for _, event := range events {
        current += event.Delta
        if current > best {
            best = current
        }
    }
    return best, true
}
```

Для полуинтервалов событие `-1` должно идти раньше `+1` в одной координате.
Иначе `[1, 3)` и `[3, 5)` на мгновение дадут ложную одновременность `2`.

Время O(n log n), память O(n). Если координаты небольшие и целочисленные,
события можно агрегировать в разностном массиве. Если координаты огромные, но
редкие, сортировка только существующих границ не зависит от величины координат.

## Как работает sweep line

Сканирующая прямая (`sweep line`) превращает геометрическую или временную задачу
в упорядоченный поток событий. Алгоритм проходит координату слева направо и
поддерживает состояние активных объектов.

В задаче выше состояние — один счётчик. В более сложных вариантах активное
множество может хранить:

- минимальную правую границу в куче;
- активные высоты в ordered multiset;
- отрезки в дереве диапазонов;
- идентификаторы ресурсов для восстановления назначения.

Общий flow состоит из четырёх фаз:

1. Преобразовать каждый объект в события.
2. Определить порядок событий с одинаковой координатой.
3. Отсортировать события.
4. Обновлять активное состояние и ответ.

Третий пункт обычно даёт O(n log n). Если события уже отсортированы или
координаты допускают линейный подсчёт, стоимость можно уменьшить.

## Что выбирать

| Задача | Приём | Сложность |
| --- | --- | --- |
| Нормализовать набор пересекающихся интервалов | Сортировка + слияние | O(n log n) |
| Пересечь два нормализованных списка | Два указателя | O(n + m) |
| Найти максимум одновременных интервалов | Sweep line со счётчиком | O(n log n) |
| Назначить конкретные ресурсы | Sweep line + куча свободных/занятых ресурсов | O(n log n) |
| Много обновлений покрытия на малых координатах | Разностный массив | O(n + q) |
| Онлайн-добавление и поиск пересечений | Interval Tree или индекс БД | O(log n + k) |

`k` в последней строке — число найденных пересечений: вернуть `k` результатов
быстрее O(k) невозможно.

## Практические ограничения

- **Единая семантика времени.** API, база и код должны одинаково понимать
  окончание. Поле `ends_at` без соглашения об инклюзивности создаёт двойные
  бронирования на границе.
- **Часовые пояса.** Интервалы сравнивают в одной временной шкале, обычно UTC.
  Локальное время с переходом DST может содержать пропущенные или повторные
  часы.
- **Точность.** Округление до секунды или минуты меняет пересечение. Точность
  должна быть частью модели, а не случайным форматированием.
- **Параллельная запись.** Алгоритм на снимке не предотвращает две конкурентные
  вставки в один свободный слот. Для бронирования нужна транзакция, уникальное
  ограничение, блокировка или сериализованный владелец ресурса.
- **Размер результата.** Нормализация уменьшает число интервалов, но запрос всех
  пересечений двух плотных наборов может иметь большой output независимо от
  индекса.
- **Сортировка чисел.** Компаратор не должен возвращать `a.Start-b.Start`: разность
  может переполнить `int`. `cmp.Compare` или явные сравнения безопаснее.

## Типичные ошибки

- Не определить закрытые или полуоткрытые границы до написания сравнений.
- Склеивать соседние интервалы, хотя доменная модель считает их раздельными.
- Сортировать входной срез и неожиданно менять данные вызывающего кода.
- Проверять пересечение только по началам и забывать вложенные интервалы.
- Обрабатывать начало раньше окончания в одной точке для `[start, end)`.
- Считать пустой интервал занятым ресурсом.
- Применять два указателя к ненормализованным спискам.
- Решать конкурентное бронирование только алгоритмом в памяти без атомарности
  в хранилище.

## Interview-ready answer

**1. Что нужно уточнить перед задачей на интервалы?**

- Границы — закрытый это интервал или полуоткрытый.
- Соседство — считаются ли `[1,3)` и `[3,5)` пересечением или только касанием.
- Валидность — разрешены ли пустые интервалы и что делать при `start > end`.
- Побочный эффект — можно ли сортировать входной массив in-place.

**2. Почему после сортировки интервалы сливаются одним проходом?**

- Порядок — все возможные пересечения текущего результата идут подряд по началу.
- Состояние — достаточно последнего уже объединённого интервала.
- Стоимость — сортировка O(n log n), линейное слияние O(n).

**3. Как пересечь два отсортированных списка за O(n + m)?**

- Пересечение — начало равно максимуму начал, конец минимуму концов.
- Непустота — для полуинтервала требуется `start < end`.
- Прогресс — интервал с меньшим концом больше не пересечётся с последующими и его указатель сдвигается.

**4. Как посчитать число одновременно активных интервалов?**

- События — начало даёт `+1`, окончание `-1`.
- Порядок — для `[start, end)` окончание в одной координате идёт раньше начала.
- Ответ — максимум накопительного счётчика после сортировки событий.

**5. Почему алгоритм интервалов не решает race при бронировании?**

- Снимок — два процесса могут одновременно увидеть один и тот же свободный диапазон.
- Атомарность — проверка и запись должны быть одной транзакцией или сериализованной операцией.
- Роль алгоритма — он находит конфликт в заданном наборе, но не синхронизирует конкурентные изменения этого набора.
