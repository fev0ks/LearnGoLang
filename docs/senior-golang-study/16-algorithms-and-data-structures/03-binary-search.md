Бинарный поиск отбрасывает половину пространства на каждом шаге и работает за
`O(log n)`. Для этого нужен не обязательно массив, а монотонный предикат:
после некоторой границы его значение меняется только один раз.

---

## Шаблон

### Почему `left + (right-left)/2`, а не `(left+right)/2`

Если `left` и `right` — большие `int32` или `int64`, их сумма может переполнить тип:

```
left = 2_000_000_000, right = 2_000_000_001
(left + right) = 4_000_000_001 -> overflow для int32
```

Для индексов, где `0 <= left <= right`, безопасная формула:

```go
mid := left + (right-left)/2
```

В Go ширина `int` зависит от архитектуры. Для реального среза переполнение суммы
индексов обычно упирается в память раньше, но форма через разность не требует
этого предположения. Для произвольных знаковых границ она безопасна только при
дополнительном условии, что `right-left` само не переполняется.

### Два варианта границ

| Стиль | Инвариант | Условие цикла | Сдвиг right |
|---|---|---|---|
| Inclusive both ends | `[left, right]` | `left <= right` | `right = mid - 1` |
| Half-open | `[left, right)` | `left < right` | `right = mid` |

Inclusive — проще читается и используется по умолчанию ниже.

### Базовый шаблон Go

```go
func binarySearch(nums []int, target int) int {
    left, right := 0, len(nums)-1
    for left <= right {
        mid := left + (right-left)/2
        if nums[mid] == target {
            return mid
        } else if nums[mid] < target {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }
    return -1
}
```

## Вариант 1: классический поиск

Найти индекс `target` в отсортированном массиве; вернуть `-1`, если не найден.

```go
// Search возвращает индекс target в отсортированном nums или -1, если элемента нет.
// Время O(log n), память O(1).
func Search(nums []int, target int) int {
    left, right := 0, len(nums)-1

    for left <= right {
        mid := left + (right-left)/2

        switch {
        case nums[mid] == target:
            return mid
        case nums[mid] < target:
            left = mid + 1 // target правее
        default:
            right = mid - 1 // target левее
        }
    }

    return -1
}
```

## Вариант 2: первая позиция (lower bound)

Найти наименьший индекс, где `nums[i] >= target`.
Применяется для: первое вхождение, позиция вставки, "сколько элементов меньше target".

```go
// LowerBound возвращает наименьший индекс i, для которого nums[i] >= target.
// Если все элементы меньше target, возвращает len(nums).
// Время O(log n), память O(1).
func LowerBound(nums []int, target int) int {
    left, right := 0, len(nums) // right = len, не len-1 — ответ может быть за концом

    for left < right { // строгое неравенство: когда left == right, ответ найден
        mid := left + (right-left)/2

        if nums[mid] < target {
            left = mid + 1 // mid точно не подходит, сдвигаем левую границу
        } else {
            right = mid // mid — кандидат, сужаем правую границу до него
        }
    }

    return left // left == right — позиция первого элемента >= target
}
```

Первое вхождение `target`:

```go
func FirstOccurrence(nums []int, target int) int {
    pos := LowerBound(nums, target)
    if pos < len(nums) && nums[pos] == target {
        return pos
    }
    return -1
}
```

## Вариант 3: последнее вхождение

Найти наибольший индекс, где `nums[i] == target`; вернуть `-1`, если не найден.

Здесь важно не спутать термины. В стандартной терминологии (`std::upper_bound` в C++, `sort.SearchInts` в Go) **upper bound** — это первый индекс, где `nums[i] > target`, то есть позиция *за* последним вхождением. Функция ниже возвращает сам последний индекс, то есть `upper_bound - 1`. Разница в единицу, но именно она даёт ошибку в формуле подсчёта вхождений.

```go
// LastOccurrence возвращает наибольший индекс i, где nums[i] == target, или -1.
// Время O(log n), память O(1).
func LastOccurrence(nums []int, target int) int {
    left, right := 0, len(nums)-1
    result := -1

    for left <= right {
        mid := left + (right-left)/2

        if nums[mid] == target {
            result = mid      // запоминаем кандидата
            left = mid + 1    // продолжаем искать правее
        } else if nums[mid] < target {
            left = mid + 1
        } else {
            right = mid - 1
        }
    }

    return result
}
```

Собственно `upper bound` удобно записать тем же полуинтервальным шаблоном:

```go
// UpperBound возвращает первый индекс i, для которого nums[i] > target.
func UpperBound(nums []int, target int) int {
    left, right := 0, len(nums)
    for left < right {
        mid := left + (right-left)/2
        if nums[mid] <= target {
            left = mid + 1
        } else {
            right = mid
        }
    }
    return left
}
```

Количество вхождений `target` через границы:

```go
func CountOccurrences(nums []int, target int) int {
    first := LowerBound(nums, target)
    if first == len(nums) || nums[first] != target {
        return 0
    }
    return UpperBound(nums, target) - first
}
```

## Вариант 4: поиск в повёрнутом массиве

Отсортированный массив повёрнут в неизвестной точке: `[4,5,6,7,0,1,2]`.
Найти `target`; вернуть `-1`, если не найден.

Ключевая идея: один из двух отрезков `[left, mid]` или `[mid, right]` всегда отсортирован — определяем какой, сужаем диапазон.

```go
// SearchRotated ищет target в повёрнутом отсортированном массиве без дубликатов.
// Время O(log n), память O(1).
func SearchRotated(nums []int, target int) int {
    left, right := 0, len(nums)-1

    for left <= right {
        mid := left + (right-left)/2

        if nums[mid] == target {
            return mid
        }

        // Левая половина [left, mid] отсортирована
        if nums[left] <= nums[mid] {
            // target попадает в отсортированную левую часть?
            if nums[left] <= target && target < nums[mid] {
                right = mid - 1 // ищем слева
            } else {
                left = mid + 1 // ищем справа
            }
        } else {
            // Правая половина [mid, right] отсортирована
            // target попадает в отсортированную правую часть?
            if nums[mid] < target && target <= nums[right] {
                left = mid + 1 // ищем справа
            } else {
                right = mid - 1 // ищем слева
            }
        }
    }

    return -1
}
```

## Вариант 5: бинарный поиск на ответе

Задача: за `D` дней доставить посылки весами `weights` — найти минимальную грузоподъёмность корабля.

Пространство поиска — не индексы, а значения `[max(weights), sum(weights)]`.
Предикат `canShip(capacity)` монотонен: если `capacity` достаточна, то любая большая тоже достаточна.
Предусловия примера: `weights` не пуст, все веса положительны, `days > 0`, а
их сумма помещается в `int`.

```go
// ShipWithinDays возвращает минимальную грузоподъёмность, при которой все посылки
// доставляются за days дней. Время O(n · log(сумма весов)), память O(1).
func ShipWithinDays(weights []int, days int) int {
    // Нижняя граница: корабль должен вмещать хотя бы самый тяжёлый груз.
    // Верхняя граница: берём всё за один день.
    left, right := weights[0], 0
    for _, w := range weights {
        if w > left {
            left = w
        }
        right += w
    }

    for left < right {
        mid := left + (right-left)/2

        if canShip(weights, days, mid) {
            right = mid // mid достаточен — ищем меньше
        } else {
            left = mid + 1 // mid недостаточен — нужно больше
        }
    }

    return left
}

// canShip проверяет, хватает ли грузоподъёмности capacity, чтобы уложиться в days дней.
func canShip(weights []int, days, capacity int) bool {
    currentLoad, daysNeeded := 0, 1

    for _, w := range weights {
        if currentLoad+w > capacity {
            daysNeeded++ // начинаем новый день
            currentLoad = 0
        }
        currentLoad += w
    }

    return daysNeeded <= days
}

```

Если входной контракт не гарантирует эти предусловия, функция должна вернуть
ошибку до вычисления границ. В частности, `slices.Max` на пустом срезе вызывает
panic, поэтому простая замена цикла на него не убирает необходимость валидации.

Паттерн "поиск на ответе" в общем виде:

```go
// BinarySearchOnAnswer находит минимальное значение x в [lo, hi],
// для которого predicate(x) == true (predicate монотонен: false...false, true...true).
// Предусловие: predicate(hi) == true, то есть допустимый ответ существует.
func BinarySearchOnAnswer(lo, hi int, predicate func(int) bool) int {
    for lo < hi {
        mid := lo + (hi-lo)/2
        if predicate(mid) {
            hi = mid
        } else {
            lo = mid + 1
        }
    }
    return lo
}
```

## Вариант 6: целочисленный sqrt(x)

Найти наибольшее целое `k`, такое что `k*k <= x`, для `x >= 0`.
Пространство поиска: `[0, x]`.

```go
// MySqrt возвращает целую часть квадратного корня из x.
// Время O(log x), память O(1).
func MySqrt(x int) int {
    if x < 0 {
        return -1 // для рабочего API лучше вернуть ошибку
    }
    if x < 2 {
        return x
    }

    left, right := 1, x/2 // sqrt(x) <= x/2 для x >= 4

    for left <= right {
        mid := left + (right-left)/2

        // mid <= x/mid эквивалентно mid*mid <= x, но не переполняет int.
        if mid <= x/mid {
            left = mid + 1 // mid подходит, но ищем больше
        } else {
            right = mid - 1 // mid слишком большой
        }
    }

    // right — наибольшее k, при котором k*k <= x
    return right
}
```

Сравнение через деление важно и на 64-битной платформе: для значений `x`,
близких к `math.MaxInt`, произведение `mid*mid` тоже переполняет `int`.

## Готовое в стандартной библиотеке

Писать бинарный поиск руками нужно на собеседовании и в задачах с нестандартным предикатом. В рабочем коде для обычного поиска по срезу есть готовое, и оно же задаёт правильную терминологию.

Официальные контракты: [`slices.BinarySearch`](https://pkg.go.dev/slices#BinarySearch)
и [`sort.Search`](https://pkg.go.dev/sort#Search).

| Что нужно | Чем делать | Что возвращает |
| --- | --- | --- |
| Найти элемент в упорядоченном срезе | `slices.BinarySearch(s, v)` | индекс и признак `found`; индекс — это lower bound |
| То же со своим сравнением | `slices.BinarySearchFunc(s, target, cmp)` | то же самое |
| Поиск по произвольному монотонному предикату | `sort.Search(n, f)` | наименьший `i`, для которого `f(i)` истинно |
| Поиск в срезе `[]int`, `[]float64`, `[]string` | `sort.SearchInts` и родственные | позиция вставки |

**Контракт при отсутствии элемента.** `slices.BinarySearch` возвращает позицию
вставки, а не `-1`, поэтому проверять нужно второе возвращаемое значение, а не
индекс. Проверка на Go 1.26:

```text
slices.BinarySearch([1 3 3 3 5 7], 3) = индекс 1, найдено true   ← lower bound
slices.BinarySearch([1 3 3 3 5 7], 4) = индекс 4, найдено false  ← позиция вставки
```

Посчитать вхождения можно как `upper - lower`. Нижнюю границу даёт
`sort.SearchInts(nums, x)`, а верхнюю —
`sort.Search(len(nums), func(i int) bool { return nums[i] > x })`. Запись через
`sort.SearchInts(nums, x+1)` короче, но неверна для `x == math.MaxInt` из-за
переполнения `x+1`.

`sort.Search` — самый общий из них и прямо соответствует «бинарному поиску на ответе»: он принимает размер пространства и монотонный предикат, а не срез.

## Типичные ошибки

### Бесконечный цикл: `left = mid` вместо `left = mid + 1`

```go
// Неправильно: когда left == right == mid, left не продвигается — цикл не завершится
if nums[mid] < target {
    left = mid // BUG
}

// Правильно
if nums[mid] < target {
    left = mid + 1
}
```

Причина: если `left == right`, то `mid == left`. Присвоение `left = mid` не меняет состояние — цикл зависает.

### Выход за пределы: `right = len(nums)` в классическом варианте

```go
// Неправильно: right = len(nums) — обращение к nums[mid] на последнем шаге
// может дать panic: index out of range
left, right := 0, len(nums) // BUG для inclusive-варианта

// Правильно для inclusive [left, right]
left, right := 0, len(nums)-1

// right = len(nums) корректен только в half-open варианте,
// где условие цикла left < right и right никогда не разыменовывается
```

### Переполнение mid

```go
// Небезопасно в языках с фиксированной шириной int
mid := (left + right) / 2 // overflow если left + right > INT_MAX

// Всегда безопасно
mid := left + (right-left)/2
```

## Когда применять

| Признак задачи | Применить |
|---|---|
| Массив отсортирован, нужно найти элемент | Классический бинарный поиск `O(log n)` |
| Нужна позиция вставки или первое/последнее вхождение | Lower bound / upper bound |
| Массив отсортирован, но повёрнут | Бинарный поиск с проверкой отсортированной половины |
| Функция результата монотонна (false...true) | Бинарный поиск на ответе |
| Нужно `O(log n)` вместо `O(n)` по числовому диапазону | Бинарный поиск на ответе |
| Задача "минимум/максимум при ограничении" | Бинарный поиск на ответе + предикат-проверка |

Сигналы, что задача решается бинарным поиском на ответе:
- в условии есть "минимальный X при котором ...";
- есть "максимальный X при котором ...";
- можно написать функцию `feasible(x) bool`, которая монотонна.

## Interview-ready answer

**1. Что именно требуется от данных, чтобы бинарный поиск был применим?**

- Требование — не сортировка сама по себе, а монотонность признака: слева от границы предикат ложен, справа истинен.
- Частный случай — в отсортированном массиве предикат «элемент не меньше искомого» монотонен.
- Обобщение — массива может не быть: пространством поиска становится числовой диапазон возможных ответов.
- Ловушка — на немонотонном предикате алгоритм обычно возвращает правдоподобный, но неверный результат без ошибки.

**2. Почему `mid := left + (right-left)/2`, а не `(left+right)/2`?**

- Риск — сумма двух больших индексов может переполнить тип.
- Безопасная область — при `0 <= left <= right` разность `right-left` помещается в тот же тип, поэтому форма через разность безопасна.
- Go — ширина `int` зависит от архитектуры; на реальных размерах срезов память обычно заканчивается раньше переполнения индексов.
- Ограничение — для произвольных знаковых границ отдельно нужно доказать, что `right-left` не переполняется.

**3. Чем lower bound отличается от upper bound?**

- Нижняя граница — первый индекс, где элемент не меньше искомого; верхняя — первый индекс, где элемент строго больше.
- Подсчёт — разность границ равна количеству вхождений, а последнее вхождение лежит на `upper - 1`.
- Различие — «последнее вхождение» и upper bound отличаются на единицу и не взаимозаменяемы.
- Go — `slices.BinarySearch` возвращает нижнюю границу, а верхнюю безопасно искать через `sort.Search` с предикатом `nums[i] > x`.

**4. Как искать в отсортированном, но повёрнутом массиве?**

- Инвариант — без дубликатов хотя бы одна половина относительно `mid` отсортирована.
- Выбор половины — его определяет сравнение `nums[left]` и `nums[mid]`.
- Сужение — если target входит в диапазон отсортированной половины, поиск продолжается там, иначе в другой.
- Дубликаты — при `nums[left] == nums[mid] == nums[right]` сравнение не
  показывает, с какой стороны находится поворот; приходится сжимать границы,
  и худший случай деградирует до O(n).

**5. Что такое бинарный поиск по ответу и как его распознать?**

- Пространство — поиск идёт по диапазону значений ответа, а не по индексам массива.
- Предикат — каждый шаг проверяет монотонное условие `feasible(x)`.
- Сигнал — формулировки «минимальное X, при котором» и «максимальное X, при котором» подсказывают этот приём, но монотонность нужно доказать.
- Стоимость — O(log(диапазон)) вызовов предиката; для доставки проверка O(n), итого O(n · log(сумма весов)).

**6. Какие три ошибки в реализации встречаются чаще всего?**

- Нет прогресса — `left = mid` может не изменить состояние; нужно исключить проверенный `mid` через `mid+1`.
- Несогласованные границы — `right = len(nums)` вместе с `left <= right` допускает индекс за концом среза.
- Смешение шаблонов — `[left, right)` и `[left, right]` требуют разных условий цикла и обновлений.
- Профилактика — инвариант выбирают до кода и проверяют после каждого сдвига границ.
