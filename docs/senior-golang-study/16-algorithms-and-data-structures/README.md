## Как читать

1. [00](./00-patterns-overview.md) — начать с карты раздела и научиться распознавать паттерн по условию.
2. [01](./01-time-and-space-complexity.md) — закрепить оценку сложности, на которую опираются остальные материалы.
3. Затем [02](./02-two-pointers-and-sliding-window.md) и [03](./03-binary-search.md) как базовые линейные паттерны.
4. После линейных паттернов перейти к [09](./09-prefix-sums-and-difference-arrays.md), [10](./10-monotonic-stack-and-deque.md) и [11](./11-intervals-and-sweep-line.md): они показывают, как использовать порядок и переиспользовать уже вычисленный агрегат.
5. [04](./04-trees-and-graphs.md), [12](./12-weighted-graphs-and-shortest-paths.md) и [05](./05-dynamic-programming.md) требуют больше времени: здесь важны инварианты обхода, ограничения весов и правильный выбор состояния.

Разбор конкретных задач с решениями — в [12-interview-practice/coding-tasks](../12-interview-practice/coding-tasks/README.md). Здесь — приёмы, там — их применение под таймером.

## Что важно уметь

- Объяснить O(1), O(log n), O(n), O(n log n), O(n²) и назвать пример на каждый класс.
- Заметить O(n²) там, где хватит O(n) с хеш-таблицей, — самая частая ошибка на практике.
- Написать два указателя, скользящее окно и бинарный поиск без подсказок, не путаясь в границах.
- Отличить задачу для скользящего окна от задачи для префиксной суммы и выбрать структуру для online-обновлений диапазона.
- Узнать монотонный стек по формулировке «первый больший/меньший», а монотонный дек — по экстремуму в движущемся окне.
- Зафиксировать семантику границ интервала и корректно обработать события с одинаковой координатой.
- Обойти дерево итеративно: в ширину через очередь, в глубину через стек.
- Выбрать BFS, 0-1 BFS, Dijkstra или Bellman-Ford по диапазону весов и объяснить, почему отрицательное ребро ломает Dijkstra.
- Применить шаблон перебора с возвратом и объяснить, что именно отсекается.
- Использовать `container/heap` для top-K вместо полной сортировки.
- Объяснить разницу мемоизации и табуляции и назвать, когда какой вариант уместнее.
- Назвать сложность стандартных операций Go и границы гарантии: `append`, поиск в `map`, `slices.Sort`.
