# 601. Human Traffic of Stadium (Hard)

> LeetCode 601 · https://leetcode.com/problems/human-traffic-of-stadium/
> Тема: «острова» подряд идущих строк (gaps-and-islands), трюк `id - ROW_NUMBER()`.

## Условие

```
Stadium: id (PK, последовательные целые) | visit_date | people
```

Вернуть строки, входящие в серии **из трёх и более подряд идущих по `id` записей**,
у каждой из которых `people >= 100`. Результат отсортировать по `visit_date`.

## Почему именно это спрашивают

Это эталонная задача класса **gaps-and-islands**: найти непрерывные группы строк,
удовлетворяющих условию. Решается красивым трюком с разностью `id` и номера строки.

## Идея: `id - ROW_NUMBER()` маркирует остров

Отфильтруем строки с `people >= 100` и пронумеруем их по `id`. У подряд идущих по
`id` строк разность `id - ROW_NUMBER()` постоянна — это и есть идентификатор «острова».
Как только в последовательности `id` появляется дыра (строка с people < 100
выпала из фильтра), разность меняется.

```
id  people  rn  id-rn
2   109      1    1   ┐
3   150      2    1   ├ остров A (длина 3 → подходит)
4   100      3    1   ┘
6   120      4    2   ┐ остров B (длина 1 → нет)
7    99 (отфильтрован)
8   188      5    3   ┐ остров C ...
```

## Решение

```sql
WITH high AS (
  SELECT id,
         visit_date,
         people,
         id - ROW_NUMBER() OVER (ORDER BY id) AS grp
  FROM Stadium
  WHERE people >= 100
)
SELECT id, visit_date, people
FROM high
WHERE grp IN (
  SELECT grp
  FROM high
  GROUP BY grp
  HAVING COUNT(*) >= 3
)
ORDER BY visit_date;
```

- CTE `high` оставляет только дни с посещаемостью ≥ 100 и проставляет каждой строке
  метку острова `grp = id - row_number`.
- Подзапрос находит острова длиной ≥ 3.
- Снаружи выбираем строки этих островов, сортируем по `visit_date`.

## Подводные камни

- Трюк опирается на то, что `id` — последовательные целые. Если бы `id` имели дыры
  *вне* фильтра, нужно было бы нумеровать иначе; здесь это безопасно, т.к. `ROW_NUMBER`
  считается уже по отфильтрованному набору.
- Частая ошибка — пытаться решить через тройной self-join по `id, id+1, id+2`: для
  «3 и более подряд» это даёт раздутый и плохо обобщаемый запрос.

## Что проверяет на собесе

Распознавание паттерна gaps-and-islands и владение трюком `id - ROW_NUMBER()`.
Тот же приём решает «непрерывные периоды активности», «streak'и логинов» и т.п.
