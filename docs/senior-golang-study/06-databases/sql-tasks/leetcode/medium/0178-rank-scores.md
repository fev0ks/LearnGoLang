# 178. Rank Scores (Medium)

> LeetCode 178 · https://leetcode.com/problems/rank-scores/
> Тема: оконные функции ранжирования, `RANK` vs `DENSE_RANK`.

## Условие

```
Scores: id (PK) | score
```

Отранжировать результаты по убыванию `score`. Правила:
- одинаковые `score` получают одинаковый ранг;
- после группы равных **нет пропусков** в нумерации (1, 1, 2, 3, а не 1, 1, 3, 4);
- вывод отсортирован по `score` по убыванию.

## Почему именно это спрашивают

Это эталонная задача на разницу между `RANK()` и `DENSE_RANK()`. «Без пропусков» —
прямое указание на `DENSE_RANK`.

## Решение

```sql
SELECT score,
       DENSE_RANK() OVER (ORDER BY score DESC) AS "rank"
FROM Scores
ORDER BY score DESC;
```

`DENSE_RANK()` нумерует уникальные значения `score` подряд: равные строки делят ранг,
а следующий ранг — без скачка.

## RANK vs DENSE_RANK vs ROW_NUMBER

| Функция | Поведение на tie (3, 3, 5) | Результат рангов |
| --- | --- | --- |
| `ROW_NUMBER()` | уникальный номер каждому | 1, 2, 3 |
| `RANK()` | равным один ранг, дальше с пропуском | 1, 1, 3 |
| `DENSE_RANK()` | равным один ранг, дальше без пропуска | 1, 1, 2 |

## Подводные камни

- `rank` — зарезервированное слово (имя оконной функции). В Postgres колонку-алиас
  нужно заключать в двойные кавычки: `AS "rank"`. На LeetCode/MySQL проходит и `Rank`.
- Использовать `RANK` вместо `DENSE_RANK` → появятся пропуски, тест не пройдёт.

## Что проверяет на собесе

Знание семейства ранжирующих оконных функций и осознанный выбор под формулировку.
