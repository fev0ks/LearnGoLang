# 180. Consecutive Numbers (Medium)

> LeetCode 180 · https://leetcode.com/problems/consecutive-numbers/
> Тема: соседние строки через оконные `LEAD`/`LAG`, поиск серий.

## Условие

```
Logs: id (PK, последовательные целые) | num
```

Найти все значения `num`, которые встречаются **не менее трёх раз подряд** (в порядке
`id`). Каждое такое значение вывести один раз.

## Почему именно это спрашивают

Классика «работы с соседними строками». В реляционной модели нет понятия «следующая
строка» — его дают оконные функции `LEAD`/`LAG`. Альтернатива — self-join по `id+1`.

## Решение через LEAD

```sql
SELECT DISTINCT num AS ConsecutiveNums
FROM (
  SELECT num,
         LEAD(num)    OVER (ORDER BY id) AS next1,
         LEAD(num, 2) OVER (ORDER BY id) AS next2
  FROM Logs
) t
WHERE num = next1 AND num = next2;
```

Для каждой строки `LEAD` подтягивает значения следующих двух строк по порядку `id`.
Если все три равны — это начало серии длиной ≥ 3. `DISTINCT` убирает повторы, если
серия длиннее трёх.

## Альтернатива через self-join

```sql
SELECT DISTINCT l1.num AS ConsecutiveNums
FROM Logs l1
JOIN Logs l2 ON l2.id = l1.id + 1 AND l2.num = l1.num
JOIN Logs l3 ON l3.id = l1.id + 2 AND l3.num = l1.num;
```

Читается прямолинейно, но завязан на то, что `id` идут без дыр. `LEAD` устойчивее:
он использует порядок строк, а не арифметику по `id`.

## Подводные камни

- Если `id` могут иметь пропуски, self-join по `id+1` сломается, а оконный вариант —
  нет (он опирается на `ORDER BY id`, а не на конкретные значения).
- Не забыть `DISTINCT`: длинная серия одинаковых чисел иначе даст дубликаты.

## Что проверяет на собесе

Умение анализировать соседние строки и сравнить оконный подход с self-join по
устойчивости к пропускам в ключе.
